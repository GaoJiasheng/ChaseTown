# 角色资产重压可行性分析（B1 起步）

> 日期：2026-09-03 · 状态：**分析完成，未改动任何资产**
>
> 背景：`public/models` 目标 24,631,610 B，当前 37,964,248 B，超出 13,332,638 B。
> 三个角色的三档资产合计 24,082,664 B，占目标的 97.8%，是唯一有意义的削减对象。

## 1. 字节分布实测

| 资产 | 字节 | 是否部署 |
|---|---:|---|
| `police.glb` | 7,645,844 | 否（发布剪枝） |
| `kid.glb` | 4,471,520 | 否 |
| `villain.glb` | 3,123,624 | 否 |
| `kid-lod1.glb` | 2,935,512 | 否 |
| `police-bootstrap.glb` | 1,926,584 | **是**（按需） |
| `kid-bootstrap.glb` | 1,561,604 | **是**（首绘） |
| `villain-lod1.glb` | 1,526,192 | 否 |
| `villain-bootstrap.glb` | 891,784 | **是**（首绘） |

`high` 与 `lod1` 三档合计 19,702,692 B **不进入部署产物**，因此重压它们只改善仓库口径，
不改变部署体积与首屏预算。这也意味着这部分不存在面向玩家的画质风险，
但它们是 bootstrap 的派生来源，画质仍会向下游传播。

## 2. 单点最大机会：Police 皮肤贴图

`police.glb` 的 89%（6,879,074 B）是纹理，7 张图中一张就占了近半：

| 贴图 | 尺寸 | 字节 | 编码密度 |
|---|---|---:|---:|
| `young_lightskinned_male_diffuse2` | 2048×2048 | **3,653,212** | **6.97 bpp** |
| `Police_v22_CasualSuit_Normal_1K` | 1024×1024 | 809,547 | 6.18 bpp |
| 其余五张 768² | 768×768 | 428,522–538,950 | 5.8–7.3 bpp |

对照 Kid 的同规格贴图：

| 贴图 | 尺寸 | 字节 | 编码密度 |
|---|---|---:|---:|
| `Char_Kid_A2_Semantic_BaseColor_2K` | 2048×2048 | **940,777** | **1.79 bpp** |

两者**同为 UASTC + Zstandard 超压缩、同分辨率、同 12 级 mip**，
编码密度却相差 3.9 倍。差异不在分辨率，在编码。

## 3. 结论与边界

- 可确认：Police 皮肤贴图是全部角色资产中密度最高的单项，若能压到 3 bpp 量级，
  单张可省约 2.1 MB；压到 Kid 的 1.79 bpp 则约省 2.7 MB。
- **不可据此承诺目标可达**：Kid 那张是语义平涂烘焙（低熵），
  Police 这张是 MakeHuman 照片级皮肤（高熵），两者可压缩性天然不同。
  1.79 bpp 不是 Police 的可达值，只是同管线下的参照。
- 即便 Police 高模减半，仓库口径仍差约 1 万 KB 量级，
  达标需要三个角色三档整体重压，不是单点改动。

## 4. 施工必须满足的门禁（未执行）

任何重压都必须重跑完整 M1 验收链，缺一不可：

1. 重新派生 `lod1` 与 `bootstrap`，并更新 `art-source/reports/character-*.json` 冻结报告；
2. `npm run art:character-runtime:check`、`art:runtime-ktx2:check`、`art:runtime-gate:check`；
3. bootstrap 对参考档的视觉忠实度配对（silhouette IoU ≥0.9999、RGB MAE ≤1）；
4. 解码后 stddev 硬门禁（BaseColor ≥8、Normal ≥4、AO ≥3）与 glTF Validator Error=0；
5. 21 关节、每关节恰好一次、12/8/5 clip 契约逐项不变；
6. 正式机位角色高度合同：桌面 34–58 px、触屏 42–68 px；
7. 首屏 encoded-transfer 不得上升（当前余量 36,048 B）。

因涉及已验收资产且需完整门禁复跑，本批只做分析，不改动任何资产。
