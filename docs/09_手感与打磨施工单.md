## 0. 施工规则（先读）

1. **分三批施工，每批独立可验收**：P0（可玩性）→ P1（观感）→ P2（反馈与健壮性）。一批做完、自测、报告后再进下一批。不允许三批混在一个大 diff 里。
2. **只允许改**：`app/chasing-game.tsx`、`app/globals.css`、`tests/**`。若单文件拆分（P2-7）获准执行，允许新建 `app/game/**`。**不允许碰** `public/models/**`、`art-source/**`、`tools/**`、`docs/**`（除在报告中引用）。

4. **调参项给的是起始值**，允许 ±20% 内自行微调，但必须在报告里写出最终值和理由（用 §5 的自测方法支撑）。

## P0 — 可玩性（追逐规则成立）

### P0-1 视线遮挡（最高优先级）

**现状**：`chasing-game.tsx:726` 追捕者感知是 `distance < 7` 纯距离判定，**隔墙可见、锁定后永不丢失**。玩家没有任何利用迷宫甩开追捕者的可能，这是可玩性差的第一根源。GDD §6 定义的是"视锥/视线 + 丢失后搜索"，未实现。

**施工**：
- 写一个网格视线函数 `hasLineOfSight(a: Point, b: Point): boolean`：在 MAZE 网格上从 a 到 b 直线采样（DDA/Bresenham，步长 ≤0.5 格），任一采样点落在墙格即不可见。
- 感知条件改为：`distance < 感知半径 && hasLineOfSight(villain, player)`。
- 丢失目标后进入**搜索**：记录最后一次看见玩家的位置 `lastKnown`，先走到 `lastKnown`；到达后原地停留 2.5s（可用现有巡逻移动逻辑，目标点换成 lastKnown）；期间重新看见则继续追，超时则回到巡逻。这是 GDD §6 状态表里本来就有的 `Search` 状态，不算新功能。
- 把 `lastKnown` 与当前 AI 状态（`chase/search/patrol`）加进 `__CHASING_QA__.getState()` 返回值。

**验收**：`?qa=1` 下用 `setPositions` 把玩家放在与追捕者同距离 5 格、但隔一堵墙的位置 → state 必须是非 chase；移除遮挡（放到同走廊）→ 必须进入 chase。两个用例都要在报告里给出实际 getState 输出。

### P0-2 开局即锁定

**现状**：追捕者出生 (1,7)，玩家 (1,1)，距离 6 < 感知半径 7，开局瞬间被盯上，GDD 玩法循环的"观察迷宫"阶段不存在。

**施工**：感知半径降为 **5.5**；配合 P0-1 的视线判定后，用 §5 方法确认开局 3 秒内（含 1.5s 延迟）追捕者不处于 chase 状态。若仍锁定，把出生点后移一格（如 (1,8)）并报告。

### P0-3 追捕者转向惯性

**现状**：`chasing-game.tsx:695` 朝向每帧 `atan2` 硬切，BFS 每帧重算最优路径，追捕者是不会犯错的导弹；GDD 要求"转弯更笨、玩家靠拐弯甩开"。

**施工**：
- 给追捕者维护一个**朝向角**，每帧向目标方向以最大角速度 **3.2 rad/s** 收敛（玩家不设限）。
- 实际位移沿当前朝向而非目标方向；当朝向与目标方向夹角 >90° 时移速乘 0.45（急转弯明显减速）。
- 视觉朝向（`actor.rotation.y`）直接用这个朝向角，顺便消除模型旋转瞬切。

**验收**：直角弯道场景中玩家贴弯逃跑，追捕者过弯后与玩家的距离应拉大。报告中用 `?qa=1` 连续采样两者距离变化佐证（弯前 vs 弯后）。

### P0-4 输入方向与屏幕对齐

**现状**：相机方位向量 `(0.446, 0.668, 0.595)`（`chasing-game.tsx:419`），而 W/↑ 走世界 -z。实测按"上"角色朝屏幕右上约 37° 移动，玩家全程在做心理旋转。

**施工**：把键盘/触屏输入向量按相机在地面投影的偏航角旋转后再用于位移：`screenUp = normalize(-dir.x, -dir.z)`，`screenRight` 为其顺时针垂直向量，`move = screenRight * dx + screenUp * (-dy)`。碰撞检测已是逐轴判定，斜向移动无需改动。**不改相机本身**。

**验收**：只按 W 时，`__CHASING_QA__` 连续两帧玩家位置差向量投影到屏幕坐标后，与屏幕正上方夹角 <5°。

### P0-5 玩家贴墙穿模

**现状**：碰撞为 `Math.round` 点采样（`chasing-game.tsx:93`），角色身体可视穿入墙体约 0.3m。

**施工**：位移合法性判定加碰撞边距 **0.18 格**：对目标位置 x±margin / y±margin 的采样点都要求可行走（保持逐轴分离判定以保留贴墙滑行手感）。

**验收**：贴墙直行时角色网格不再与墙相交（截图佐证）；走廊内正常移动、拐角不卡死（用 §5 自动跑一遍全程路线确认可通关）。

### P0-6 胜负结算节奏

**现状**：被抓/到达出口的瞬间直接弹结算卡，无过渡。GDD §5.4：失败应"淡出 → 约 0.8s → 重开"；胜利面板应显示用时。

**施工**：
- 抓住判定触发后：先进入 0.6s 的"定格"（玩家与追捕者停止移动、镜头保持），期间画面用 CSS 叠层做快速变暗/泛红，然后再显示结算卡。实现方式限定为 phase 里加一个短暂的中间态或定时器，不引入新系统。
- 胜利卡片 `<h2>` 加上用时：如"警察在出口等到了你 · 用时 {elapsed}s"（`elapsed` 现成）。

### P0-7 开局 1.5s 缓冲可视化

**现状**：追捕者静止 1.5s 后突然爆发，无任何提示。

**施工**：复用现有 label/badge 系统：缓冲期内追捕者头顶标签显示倒计时（"1.5s"→"1s"→…或简化为变色的"!"），缓冲结束恢复"追捕者"。不新增 UI 系统。

## P1 — 观感打磨

### P1-1 环境反射贴图（性价比最高的一条）

**现状**：`chasing-game.tsx:150` 给所有材质设了 `envMapIntensity = 1.25`，但 `scene.environment` 从未设置——**这行完全空转**，角色与道具因此发平、塑料感。

**施工**：用 three 内置 `RoomEnvironment` + `PMREMGenerator` 生成环境贴图赋给 `scene.environment`（在 renderer 创建后一次性生成，卸载时 dispose）。零新资产。

**验收**：前后对比截图（同机位）；确认无控制台警告。

### P1-2 道具投影 + 阴影参数

**现状**：`fitProp → flattenStatic`（`chasing-game.tsx:169`）把 castShadow 全关了，警车/树/警局/储物柜等全部没有接触阴影，呈"贴纸悬浮感"。`sun.shadow` 未设 bias。

**施工**：
- `flattenStatic`/`fitProp` 增加 castShadow 参数，对大件道具（car、tree、station、locker、basketball、bench、blackboard、podium）开启投影；小件（books、backpack、trash、extinguisher 等）保持关闭控制成本。
- `sun.shadow.bias = -0.0005`、`normalBias = 0.02`（防阴影痤疮），调后检查无漏光。

### P1-3 角色动作瞬切消除

**现状**：`moving` 布尔一翻转四肢立刻回位（`chasing-game.tsx:338`）；步态频率固定 `0.013*ms` 与实际移速无关；玩家模型朝向硬切。

**施工**：
- 每个角色维护 `gaitWeight`（0↔1，约 0.15s 线性渐变），摆臂/抬腿幅度乘以它，起步停步不再跳变。
- 步态相位改为按实际位移速度积分（速度为 0 时相位不推进），跑动频率与移速视觉匹配。
- 玩家与警察的 `rotation.y` 同样加角度阻尼（可复用 P0-3 的 lerpAngle 工具），消除 180° 一帧掉头。

### P1-4 标签与光环淡出

**现状**：三个角色的黑底标签 + 脚下圆环 `depthTest:false` 永远置顶，教学价值只在前几秒，之后是持续的视觉噪音。

**施工**：进入 playing 后 4 秒，标签与圆环透明度渐隐到 0（材质 opacity 动画即可）；threat > 0.6 时追捕者的标签/圆环渐显回来；回到 ready/结算态全部恢复显示。

### P1-5 铺装重复感

**现状**：所有地板/墙体 instance 同一朝向，平铺感强。

**施工**：在 `buildCore` 里给地板类 instance 按格子坐标伪随机（确定性 hash，不用 `Math.random`，保证两次加载一致）追加 0/90/180/270° 旋转；直墙段同理做 0/180° 翻转。视觉验证拼缝无错位（墙件若非对称则跳过墙、只做地板，报告说明）。

### P1-6 警察活化

**现状**：警察不进 `syncActor`，完全冻结如蜡像；胜利文案"警察在出口等到了你"无支撑。

**施工**：给警察每帧调用一次 idle 分支的动作（呼吸浮动）；当玩家距出口 <4 格时，警察朝向玩家方向阻尼转身。不加任何新动画系统。

### P1-7 曝光微调

**现状**：`toneMappingExposure 1.28` + Hemisphere 2.75 + Sun 3.5，地砖高光发白。

**施工**：曝光降至 **1.12** 起步，配合 P1-1 的环境光贡献重新平衡三个光强，以"地砖纹理清晰可辨、阴影处角色仍可读"为准，前后对比截图。

## P2 — 反馈与健壮性

### P2-1 危险泛红

**现状**：`threat` 值每帧已算好（`chasing-game.tsx:744`，驱动相机用），但 GDD §10 的"屏幕边缘泛红"未实现。

**施工**：把 threat 节流（每 ~120ms）写入挂载容器的 CSS 变量（如 `--threat`），CSS 里用一层 `pointer-events:none` 的径向渐变红色 vignette，透明度绑定该变量。中心区域必须保持通透（GDD 要求不遮挡操作区）。

### P2-2 WebAudio 合成音效（可选，无资产依赖）

**施工**（若做）：不引入任何音频文件，用 WebAudio 合成：心跳（低频振荡，频率/音量随 threat）、脚步（滤波噪声短脉冲，与 P1-3 的步态相位同步）、胜/负各一个短 stinger。必须在用户首次点击"开始"之后再创建/恢复 AudioContext（自动播放策略）；结算与暂停时停止。做不完可整条跳过，但要在报告里明确说明。

### P2-3 失焦卡键

**现状**：Mac 上 Cmd 组合键吞 keyup，切窗口回来角色自走（验收清单 C1 明确要求处理）。

**施工**：`window` 的 `blur` 与 `visibilitychange`（hidden）时 `keys.current.clear()`。

### P2-4 GPU 资源释放

**现状**：卸载只调 `renderer.dispose()`（`chasing-game.tsx:787`），场景内 geometry/material/texture 未释放；React dev 严格模式双挂载必然双倍显存（验收清单 E 明确要求）。

**施工**：cleanup 中 traverse 场景 dispose 所有 geometry/material/texture（注意 InstancedMesh 与共享材质去重），同时 dispose P1-1 的 PMREM 产物。用 `renderer.info.memory` 前后对比佐证。

### P2-5 寻路节流与抖动

**现状**：追捕者 BFS 每帧全图重算 + 字符串 key Map，纯 GC 压力；格子边界处 next 目标翻跳造成路线抖动。

**施工**：路径缓存——仅当玩家或追捕者跨入新格、或 AI 状态切换时重算；沿缓存路径行进。顺带消除边界抖动。

### P2-6 HUD 距离改为路径距离

**现状**：“出口 Xm”是直线距离，隔墙显示 4m 误导玩家。

**施工**：HUD 更新时（已节流 180ms）用现有 `path()` 的路径长度 ×CELL 替代直线距离。

### P2-7 单文件拆分（单独一个 commit，禁止与行为改动混合）

**现状**：850 行单文件，GDD §7 承诺的 `app/game/` 模块划分未兑现。

**施工**：纯搬移不改行为——拆为 `app/game/{maze,ai,input,camera,actors,props,fx}.ts` 等（按 GDD §7 命名），`chasing-game.tsx` 只留组件与生命周期。拆分前后 `?qa=1` 状态输出与渲染统计（calls/triangles）必须一致，`npm run build`、`npm test` 全绿。

## 5. 自测方法与交付报告

每批提交前必须完成并在报告中附证据：

1. **构建门禁**：`npm run lint`、`npm run build`、`npm test` 全绿（贴输出摘要）。
2. **自动跑局**：用 `?qa=1&autostart=1` + `__CHASING_QA__.setPositions` 脚本化验证：
   - 正常开局→操作或瞬移玩家沿主路径→到达出口触发 `won`；
   - 玩家静止→追捕者（视线可达时）追上→触发 `lost`；
   - P0 各条的专项用例（见各条验收）。
3. **视觉证据**：P1 各条给同机位前后对比截图；控制台无报错、无资源 404。
4. **性能抽查**：`renderer.info.render.calls / triangles` 施工前后对比（QA 钩子已暴露），draw call 不得比现状显著增加（+10% 以内）。
5. **报告格式**：逐条列出 [P0-1 … P2-7] 的状态（完成/跳过+原因）、最终参数值、证据位置。禁止只写布尔结论。

## 7. P0 复验记录与追加项（2026-07-15，独立复核后追加）

### 7.1 P0 复验结论

P0-1 至 P0-7 全部验收通过。证据：`npm run lint/build/test` 全绿（12 用例，含真实函数单测）；浏览器 `?qa=1` 实测——隔墙距离 5 不追（`lineOfSight:false`、状态 patrol）、同走廊距离 5 进入追逐并持续逼近；开局 3 秒观察窗内无 chase。P0 参数按本单 §0 规则确认：出生点最终为 (7,1)，其余起始值未调。

### 7.2 复验中发现的追加项（编号沿用，进 P1/P2 批次）

**P1-0（新增，P1 批次第一件事）QA render 统计失真**
`getQaState` 读取 `renderer.info.render.calls/triangles` 时恒为 0：three 的 `renderer.info.autoReset` 默认开启，每帧渲染结束即清零，帧间快照读到的是清零后的值。这使本单 §5 要求的 draw call 前后对比证据全部失真。修法：`renderer.info.autoReset = false` 并在每帧 `render()` 后手动 `renderer.info.reset()` 之前把计数缓存进快照变量；或在 `render()` 调用后立即抓取。P1 批次所有性能证据必须建立在修好之后的读数上。

**P1-3b（并入 P1-3）追捕者碰撞边距**
P0-5 只给玩家加了边距；追捕者仍是 `canWalk` 点采样，转弯贴墙时模型可见穿墙。在 P1-3 动作打磨时给追捕者移动复用 `canPlayerOccupy`（边距可略小，如 0.14），不单独立项。

**P2-1 补充约束（危险泛红实现时生效）**
当前相机 `threat` 只按距离（smoothstep 4.5–9）计算，不区分追捕者是否真的发现玩家——隔墙巡逻、毫不知情时镜头/泛红也会紧张，误导玩家。P2-1 实现泛红时：threat 乘以 AI 状态因子（chase/search=1，patrol/delay≈0.25），相机拉远逻辑同步复用。QA 快照需暴露该最终 threat 值。

### 7.3 流程说明

P1 批次施工范围 = 本单 §P1-1 至 P1-7 + 上述 P1-0、P1-3b。P2 批次不变，另加 §7.2 对 P2-1 的补充约束。其余施工规则、自测方法（§5）与禁止事项（§6）继续全文有效。

## 8. P1 复验记录与新增项（2026-07-15，独立复核后追加）

### 8.1 P1 复验结论

P1-0 至 P1-7（含 P1-3b）全部验收通过。证据：lint/build/test 全绿（21 用例，新增 9 条 P1 单测均为真实函数测试）；浏览器实测——标签开局 4 秒后淡出、追捕者进入威胁半径时标记回显（实测 targetOpacity 随距离切换正确）；曝光重平衡后地砖纹理不再过曝；QA render 统计修复生效（autoReset=false + 帧末采样）；控制台零报错。环境贴图（RoomEnvironment+PMREM）与阴影 bias 均已生效并正确 dispose。墙体未做随机化（模块不对称），符合本单 P1-5 的豁免条款。

### 8.2 P1-0 修复后暴露的新数据（新增 P2-8）

**P2-8 Draw call 与三角面预算超标**
修好统计后首次拿到真实数字：**draw calls ≈ 350，triangles ≈ 209 万**（GDD §11 预算：draw call <150）。来源大头：每个道具 GLB 展平后仍是多个独立 mesh、角色三件套面数、阴影 pass 的二次绘制。P2 批次新增本项：

## 10. P3 批次：加载、渲染负载与移动端（2026-08-26 立项）

### P3-1 资产压缩管线（最高优先级）

- `tools/art_pipeline/` 增加运行时资产压缩步骤：GLB 用 gltfpack/meshopt（或 Draco）做几何压缩与量化；
  SharedTextures 转 WebP（约 85 质量档）。`art-source/` 源文件只读；`public/models/` 只保留压缩产物。
- 运行时接对应 decoder（three 内置 MeshoptDecoder / DRACOLoader）；环境 GLB 的外链贴图路径保持有效。
- 红线：压缩前后同机位截图目视一致；glTF Validator Error=0；控制台无解码报错、无 404。
- 验收：每个 GLB/贴图前后体积表；网络面板实测首屏阻塞字节数。目标：首屏阻塞 ≤6MB、
  `public/models` 总量 ≤12MB；达不到给出实测数字与原因，不许静默放宽。

### P3-2 迷宫阴影代理体

- 墙类 instanced 模块的投影改由不可见盒代理承担（如 colorWrite:false 的极简 BoxGeometry instanced，

- 验收：QA breakdown 中 `maze.shadowTriangles` < 5,000；总 triangles 显著下降；同机位阴影对比截图

  远处地砖在掠射角发糊。
- 验收：远景地砖对比截图；帧率无可测退化。

### P4-3 角色渲染合批与阴影瘦身（本批唯一高风险项，允许降级）

- 降级条款：若 (a) 因蒙皮结构不可安全合并，可只做 (b) 并如实报告原因；不许硬合并导致动作错位。
