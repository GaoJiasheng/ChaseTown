# 《追逐 / Chasing》系统性潜行 2.0 机制与接线合同

> 文档类型：机制与内容合同
> 生效日期：2026-07-26
> 上位方向：[`13_长期产品与技术路线图_2026-2028.md`](13_长期产品与技术路线图_2026-2028.md)
> 运行事实：以 `app/game/` 的版本化 TypeScript 合同和对应自动测试为准
> 发布事实：只由与 Git commit、构建和 Sites 版本绑定的发布记录声明

## 1. 目标与不可妥协边界

本轮把“跑、躲、等时机”扩展为一条可组合、可解释、可回放的潜行因果链：

1. 玩家移动或改变世界状态。
2. 场景留下可见、会衰减的公开证据。
3. 追捕者只能在合法观察范围内发现证据。
4. 追捕者到达证据点，完成左右巡视和后续搜索。
5. 玩家利用门楔、拐角镜、临时断电和抹迹制造有限窗口。
6. 公平节奏导演只根据公开聚合信号预告并施加有限压力。

任何实现都必须同时满足以下红线：

- AI 不得读取隐藏玩家坐标、藏点占用、真实/伪造标签或渲染层对象引用。
- 新线索不能覆盖同刻视觉证据；同一线索 ID 不能重复重置调查路线。
- 门楔只延迟追捕者，不能改变玩家通路或关闭唯一合法路线。
- 断电必须保留可读的应急照明下限，不得变成无提示的完全黑屏。
- 导演不得生成敌人、瞬移敌人、隔墙定位玩家或关闭唯一出口。
- 逻辑时序一律使用固定 simulation tick；渲染帧率不能改变结果。
- 玩家可见物件必须来自正式主题资产、批准的贴图绘制或正式特效层；禁止用简单方块、线框或调试几何充当最终物件。
- 动画、音效、HUD、3D 物件和规则必须在同一候选版本中闭合，不能先上线规则再承诺“以后补表现”。

## 2. 系统边界

| 层 | 责任 | 禁止事项 |
| --- | --- | --- |
| `stealth-evidence.ts` | 公开证据账本、衰减、容量、抹除/伪造成本、AI 安全投影 | 读取关卡占用、角色状态、Three.js 或 DOM |
| `stealth-toolbelt.ts` | 三类工具的库存、承诺、冷却、有限效果和收据 | 直接修改模拟、碰撞、AI 或渲染对象 |
| `tension-director.ts` | 依据公开聚合信号提出带预告、期限和安全证书的建议 | 接收玩家位置、朝向、视线或最近物件 |
| `stealth-expansion.ts` | 用静态 `LevelDefinition` 解析公开目标和适配公开线索 | 闭包运行时藏点占用或玩家私有状态 |
| `simulation.ts` / `chaser-fsm.ts` | 消费公开世界线索，执行到点、左右巡视、搜索和回执 | 跳过感知直接锁定玩家 |
| `chasing-game.tsx` | 固定步接线、正式 3D/动画/音频/HUD 表现、资源生命周期 | 在渲染层另造平行玩法真相 |

纯领域模块必须深度不可变、可从同一命令流重放，并对非法输入原子拒绝。表现层只能消费领域状态、事件和收据。

### 2.1 当前候选工作树的接线状态

以下内容描述当前候选工作树中已经存在的接线，不等同于“已经发布”或“线上已经通过”。最终结论仍须由绑定 Git SHA 的完整门禁、浏览器报告和 Sites 发布记录给出。

- 渲染宿主通过 `fixed-step-host.ts` 锁存渲染帧输入，再逐个固定 tick 推进模拟、证据、工具、任务、主动机关和导演；暂停、重开、切关或离开 `playing` 时会以当前权威 tick 原子重置宿主时钟和边沿输入。
- 三类工具已经使用四套主题 GLB 中彼此独立的正式语义节点。运行态工具 View 携带源节点、源资产 ID、源 GLB URL、主几何签名和 `fallbackUsed`，供专项 QA 核对主体不是运行时占位体。
- 导演已经在模拟输入构建前的固定 tick 边界推进，仍是 advisory-only；专项资源 QA 可通过只在 QA bridge 暴露的开关暂时隔离导演事件，恢复时以当前模拟 tick 重建导演状态，避免测试开关制造时间跳变。
- 临时工具附加的镜面、外圈和状态灯几何/材质使用显式所有权集合；效果结束、重置和卸载执行幂等释放。正式 GLB 克隆所共享的源资源不由单个临时 View 误释放。
- `G / C / F` 的真实键盘监听只负责把命令送入稳定的 `commands.current`；能否执行由命令内部的 `latestState` 权威模拟状态判断，不再使用可能滞后一帧的 React 展示阶段吞掉切关或场景重设后的第一次按键。

## 3. 公开证据合同

### 3.1 证据家族

| 类型 | 公开来源 | 典型产生方式 | AI 可见信息 |
| --- | --- | --- | --- |
| `footprint` | 地面表面 | 玩家非轻步移动达到步距阈值 | 位置、方向、年龄、置信度 |
| `door-state` | 门或藏具门体 | 进出藏点、放置门楔 | 门的公开状态，不含柜内占用 |
| `moved-object` | 可见物件 | 架设拐角镜或移动道具 | 物件变化，不含操作者后续位置 |
| `power-change` | 公开电网/控制台 | 玩家断电或导演照明事件 | 电力状态与公开来源 |
| `decoy-residue` | 诱饵物件 | 诱饵使用后的现场残留 | 残留状态，不标注真假 |

每条记录具有稳定 ID、公开来源、创建/失效 tick、初始置信度和固定衰减率。账本有硬容量；保留策略是 top-K，低价值脚印刷屏不能挤掉更高价值线索。

### 3.2 感知与调查

AI 查询只允许输入：

- 当前固定 tick；
- 观察者的公开位置和朝向；
- 最大观察距离、视锥与最低置信度；
- 只由静态关卡几何构建的可见/可达 capability。

查询输出必须删除证据的私有 origin。真实证据与伪造证据若公开字段相同，AI 投影必须字节等价。只改变 `HideSpotRuntimeState.occupiedByPlayer` 时，候选序列和回放 fingerprint 必须不变。

优先级固定为：

1. 同刻合法视觉；
2. 已目击的藏点进入；
3. 新鲜公开世界线索；
4. 合法听觉与环境声源；
5. 既有搜索假设。

追捕者消费世界线索后必须完成：

`前往线索点 → 抵达 → 左扫 → 右扫 → 搜索 → 一次性调查回执`

重获视觉仍需通过既有确认窗口；线索不能绕过抓捕、视线或藏点公平合同。

### 3.3 反侦察

抹迹要求玩家自由、靠近可擦除的世界证据、拥有预算且没有正在进行的工具承诺。成功后：

- 消耗明确预算；
- 锁定有限承诺 tick；
- 删除对应公开证据及其 3D 表现；
- 产生可被正常听觉系统采样的公开扰动；
- 不删除 `publicly-announced` 的基础设施事件。

伪造保留为领域能力和后续内容入口；玩家可见版本启用前必须有正式动作、正式道具、来源明确的音频和单独教学，不能只开放隐藏快捷键。

## 4. 三种潜行工具

### 4.1 门楔

- 目标只能是静态拓扑证明两侧贯通、两侧垂直方向封闭的公开窄门阈值；普通墙边不得兜底冒充门。
- 使用包含承诺、库存、冷却和自动释放。
- 收据只允许 `chaser-traversal` 延迟，玩家通路策略恒为 `always-passable`。
- 收据必须携带公开的水平/垂直穿越轴；只有追捕者沿该轴朝门槛移动并真实尝试穿越时，才触发一次咬合延迟。平行擦墙、站在相邻格或背离门槛均不得触发。
- 放置后产生 `door-state` 公开证据，追捕者可调查。
- 3D 表现从当前主题正式机关子组件提取并做主题表面处理；落地姿态、接触阴影、脉冲灯和到期回收均须完整。

### 4.2 拐角镜

- 目标只能是静态关卡几何证明存在遮挡的公开拐角。
- 拐角必须由两条互相垂直的不透明边共同证明；单墙边、直走廊两侧墙和运行时占用都不能作为拐角证明。
- 镜子提供有限距离、有限视锥和有限时长的公开观察孔径。
- 镜子只回答“追捕者是否处于该观察孔径内”，不能保存或持续透视其隐藏位置。
- 玩家自身能正常观察追捕者时，仍复用原可见性规则；镜面只补充明确的蓝色边框与文字反馈。
- 3D 表现使用主题正式装置为主体，配合物理材质镜面；圆面只作为材质细节，不能成为几何占位主体。

### 4.3 临时断电

- 只能在关卡正式主题控制台附近启动。
- 操作有承诺、明显基础设施风险、单局有限库存和自动恢复。
- 同时降低合法视觉范围并提供有限环境声遮蔽，但不修改碰撞、抓捕距离、出口或玩家身份。
- 应急可见度下限必须保留迷宫边界、角色轮廓、交互点和 HUD。
- 断电产生 `publicly-announced` 的 `power-change`，不能通过普通抹迹删除。
- 表现使用主题正式控制装置、蓝色应急光池、渐变暗场和恢复过渡；不得用纯黑全屏遮罩。

## 5. 公平节奏导演

当前版本是单追捕者、advisory-only 的受限预试点，不是读取空间状态的全能导演。

唯一合法输入：

- `runPhase`；
- 公开威胁档位 `safe / suspicious / chased`；
- 连续安全 tick、追逐 tick、脱离追逐后的 tick；
- 任务完成比例；
- 工具与反侦察资源的聚合比例；
- 由拓扑审计证明仍合法的全局路线 ID。

路线 ID 必须直接由任务软锁审计的可达完整顺序/出口生成；禁止构造没有对应路线审计记录的占位 ID。每个 tick 提交的是当前仍合法的审计路线集合。

当前建议类型：

| 事件 | 预告 | 有限效果 | 公平保护 |
| --- | --- | --- | --- |
| 广播巡检 | HUD、边框、广播声源 | 短时声音遮蔽与公开环境声 | 进入危险、资源保护或路线保护时撤销 |
| 巡逻提速 | HUD、橙色压力边框 | 追捕者平移最多有限增幅 | 仅作用于巡逻/调查；切入追逐的同一 tick、追逐和失视追赶均硬封顶为基础速度 |
| 照明降载 | HUD、灯光过渡 | 合法视距下降并生成公开电力线索 | 与玩家断电复用同一应急暗场和可读性下限，不关闭路线 |

每个事件必须经过 `warning → active → ended/cancelled → cooldown`。建议携带安全证书，记录预告时长、有限生命周期、当时合法路线和保留路线。追逐、刚脱险、资源过低、路线不足或暂停都必须触发喘息/取消保护。

## 6. 表现质量合同

### 6.1 3D 与材质

- 工具主体复用四套主题 GLB 中真实存在的语义子组件，但每个主题的门楔、拐角镜、临时断电必须绑定三套不同的源节点和主几何签名，不能通过改 wrapper 名称伪装成不同模型。运行态必须公开源 GLB、节点、几何签名和 `fallbackUsed=false` 供验收。
- 校园使用 BikeRack / WaterFountain / Wayfinding，医院使用 CrashCart / IVStation / Wayfinding，消防站使用 SafetyCones / HoseReel / Wayfinding，工厂使用 SafetyBarrier / PipeAssembly / ControlConsole。正式 GLB 承担主体体量，镜面、金属外圈与断路器发光状态灯只作为语义细节，不能反客为主。
- 足迹使用有鞋底轮廓与纹路的共享程序贴图、透明 PBR 地面材质和方向旋转，必须位于正式地坪与路线贴花上方且在运行镜头中可读；不使用调试箭头或线段。
- 所有临时 Mesh、Material、Texture、Light 必须有明确所有权；效果结束、重开、切关与卸载时成对释放。
- 足迹不得逐条创建纹理、材质、几何或动态灯；共享资源在场景卸载时一次释放。潜行工具和线索优先用正式材质的自发光响应保持可读，不得通过反复增减全局灯数量制造着色器变体。其他临时物件不能无限增加 draw call、动态灯或纹理；领域账本、收据和场景 View 都必须有硬上限。
- 角色、门楔或镜子被硬柜与其主题外壳夹在固定镜头后方时，柜体必须参加局部 camera cutout；切洞只覆盖相机到可读目标的窄走廊。玩家进入藏点观察视角后，所有柜体恢复完整不透明，不能透视柜外。

### 6.2 动画

- 工具承诺期间冻结玩家位移，但固定步、AI 和环境仍继续推进。
- 使用开始、承诺结束、效果触发、效果回收分别有清晰节拍，不把一帧状态切换冒充动画。
- 三种工具在承诺完成后执行约 10 个固定 tick 的贴地/抬升/压合缓动，运动根只改变 Transform，不逐帧创建几何、材质或灯，也不改写共享模板材质。
- 现有角色正式 `AnimationMixer` 动作继续负责移动、藏点、搜索与反应；工具不能打断不可取消的进出柜或任务接触。

### 6.3 音频

- 门楔：金属放置、受力和释放由空间 Foley 表达。
- 拐角镜：轻质器械放置，音量低但并非完全无风险。
- 临时断电：控制台动作、继电器/电网变化、应急环境层。
- 导演广播和基础设施事件必须进入现有空间声源/主题声景，不得用振荡器或临时蜂鸣占位。
- 静音、页面隐藏、暂停和音频设备不可用时，视觉与文本反馈仍完整。

### 6.4 HUD 与输入

- 桌面：`1–3` 选择工具，`G` 部署，`C` 抹迹；HUD 显示库存、阶段、证据数、预算和导演状态。
- `G / C / F` 等游戏动作必须由稳定的全局键盘监听转交给当前命令对象，并在命令内部依据最新模拟快照判断 `playing`；React HUD 的展示阶段只能决定界面，不得成为动作权限源。
- 手机：抹迹、门楔、拐角镜、临时断电四个独立且最小 44 px 的触控目标；工具第一次点击选择，已选工具再次点击部署。
- 手机必须显示一条紧凑的成功/拒绝原因，并用 `aria-live` 同步播报；不能因为隐藏桌面读数而让触屏玩家失去反馈。
- HUD 不显示隐藏 AI 状态、线索真假或墙后实时坐标。
- 高对比、减少动态和 forced-colors 必须有等价状态；颜色不是唯一信息通道。
- 工具条不得遮住角色安全画幅、交互提示、虚拟摇杆或右侧动作列。

## 7. 验收矩阵

每次改动至少执行：

1. TypeScript、ESLint、生产构建和完整单元/集成测试。
2. 证据领域：五类记录、衰减/失效、top-K、反侦察成本、不可变性、非法输入、occupancy-blind 变形测试。
3. 工具领域：三种工具的承诺、库存、冷却、自动释放、路线安全、30/60/120/144 Hz 等价。
4. 导演领域：严格输入白名单、预告/激活/结束、危险/资源/路线保护、回放 fingerprint。
5. AI 集成：世界线索到点、左右巡视、搜索、一次性回执；同刻视觉优先；相同 ID 幂等。
6. 运行态：桌面和竖屏各验证开始、移动、门楔、镜子、断电、抹迹、导演预告、藏点和重开。
7. 视觉：截图检查正式模型、足迹方向、工具落地、断电可读性、HUD 遮挡和高对比。
8. 资源：QA 通过 `?qa&qaQuality=high` 在创建 WebGLRenderer 前锁定高画质与 emergency level 0；装饰流送和淡入完全结束后，先用 8×8 离屏目标把三类正式工具模板和共享足迹送入 WebGL 一次，再只预编译一次完整静态场景。预热次数和完整场景编译次数都必须严格为 1。连续三个相同热基线样本成立后，至少四轮工具/线索创建与销毁必须让临时 View、Light、Geometry、Material、Texture、场景纹理和 WebGL program 数量严格等于热基线；画质、像素比、阴影图尺寸和 transition count 同样必须不变。
9. 诊断：控制台 error、未捕获异常、HTTP 4xx/5xx、资源加载失败均为零。

运行态工具测试必须通过真实键盘 `1–3 / G / C` 与真实触控目标驱动，不能只调用 QA bridge；截图前还必须在同一权威快照中同时等到 active effect、正式 View 和公开证据，断言 View 位于视锥内、具有最低投影尺寸，且 HUD 数量与权威账本一致。

资源生命周期专项必须暂时关闭导演，只测工具和线索自己的创建/销毁；随后重新启用导演并独立验证 `warning → active`。这一隔离只属于 QA，不得改变正式游戏默认启用导演的行为，也不得被用于掩盖导演自身的资源泄漏。

潜行专项浏览器证据链使用独立的 `chrome-headless-shell` 表面截图，并在页面应用代码启动前注入 `timer-60hz` 帧驱动和静止 CSS 动效规则。报告必须显式写入 `frameDriver`、`cssMotion`、截图 backend、源文件 fingerprint、视口、场景权威快照、资源基线与诊断数组；缺少任一字段的图片只能用于人工参考，不能作为发布证据。测试帧驱动仅服务确定性取证，不替代真实设备上的原生 rAF、交互和性能回归。

截图和报告必须记录工作树 fingerprint；只有最终提交再次构建、再次截图并与 Git SHA 绑定后，才能成为发布证据。

## 8. 返工触发器

出现任一情况立即阻断发布并返工：

- 玩家在相同公开证据下换一个隐藏柜，AI 决策发生变化；
- 工具效果结束后仍残留速度、视距、声音、灯光或碰撞修改；
- 断电使玩家看不清角色、墙边界或交互点；
- HUD 在 360×800 或 390×844 下遮挡移动/交互；
- 工具由简单方块、线条或未批准图标替代正式美术；
- 追捕者看到新线索后立刻放弃，未完成到点巡视；
- 导演没有预告、在追逐/刚脱险时加压或让合法路线数低于下限；
- 不同渲染帧率得到不同收据、路线、事件边界或终态；
- 重开/切关后临时资源持续增长；
- 自动检查通过但截图出现不可读、悬浮、穿模、过暗或构图错误。

返工后必须从受影响的最小专项测试开始，再执行完整门禁和浏览器截图；不得只修改截图或降低断言阈值。
