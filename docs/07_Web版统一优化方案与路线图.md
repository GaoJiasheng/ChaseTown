## 1. 产品判断与体验北极星

### 1.1 当前所处阶段

当前版本已经不是白盒，也不是二维或几何线条原型。它已经具备：

- 正式 Kid、Villain、Police 三个 3D 角色。
- 29 个运行时 GLB 与校园模块、主要道具。
- 起点、出口、计时、胜利、失败和重开闭环。
- 桌面键盘、移动端方向按钮、动态拉远与手动缩放。
- 核心模型加载进度、失败重试、非关键资产延后加载。
- 实例化墙地模块、静态网格合并与基础响应式页面。

这些能力应冻结为基线，不再返回 Unity，也不再用占位几何替换正式资产。

但当前体验仍然是“带追兵的 3D 校园迷宫展示”，还不是一款真正可掌握、可复玩、有情绪起伏的追逃游戏。最核心的原因是：

1. 玩家只有移动，没有可靠的观察、选择和反制。
2. AI 的发现与追踪不可读、不公平，且会隔墙读取玩家位置。
3. 地图看似有多条路，实际主要路线几乎等长，风险收益不成立。
4. 道具大多只用于展示，不参与碰撞、遮挡或互动。
5. 角色没有正式动画，整个游戏没有声音和完整胜负演出。
6. 移动端会隐藏出口信息，开局面板和方向按钮占据大量有效画面。
7. 固定地图、固定巡逻、固定出口和无成绩目标让最优解很快被记住。

### 1.2 体验北极星

第一关应成为一局 60–120 秒的校园潜行追逃：

> 玩家在有限信息下选择路线，通过转角、藏身和短时冲刺应对追捕，最终依靠警局的光、声和角色演出完成一次有起承转合的逃生。

玩家每局都应经历四个清楚的问题：

1. 我该往哪里走？
2. 追捕者是否发现了我？
3. 我现在能用什么方式脱身？
4. 下一局我能在哪个决策上做得更好？

### 1.3 核心设计原则

- **公平先于刺激**：玩家必须知道为什么被发现、为什么被抓。
- **选择先于内容量**：先让同一张地图产生路线和风险决策，再扩关卡。
- **规则先于特效**：AI、镜头、音频、UI 和动画共用同一个状态事实。
- **反制先于数值压迫**：难度主要来自信息、路线和搜索能力，不是单纯加速敌人。
- **主风格先于多风格**：当前只把一套主美术风格做完整，三风格进入 Post-VS。
- **质量与体积同时约束**：复用现有模型、动画和材质，不重新引入历史候选与重复大文件。

### 1.4 当前非目标

- 不制作第二关。
- 不增加第二个追捕者。
- 不增加战斗、武器或复杂物品栏。
- 不做多钥匙收集链。
- 不做多人、账号、云存档和在线排行榜。
- 不使用运行中随机改路或瞬移敌人的隐形作弊。
- 不在核心闭环稳定前恢复三套大体积角色资产。

## 3. 七个维度的统一优化设计

## 3.1 游戏可玩性

### 当前问题

- 当前核心循环是“选择一个方向并持续跑向出口”，过程中的有效动作只有移动。
- 一个开局方向可能迅速迎面撞上追捕者，另一个方向又能约 12 秒纯跑通关。
- 玩家不知道何时被发现，也没有可靠的断追动作。
- 储物柜、课桌、树、灌木等素材没有进入碰撞和规则。
- 失败只出现卡片，下一局没有告诉玩家应改变什么。

### 目标体验

每 5–10 秒至少出现一次可理解的微决策：

- 继续走最短路线，还是绕到遮挡更多的区域。
- 现在冲刺拉开距离，还是保持安静避免引起注意。
- 继续转角断视野，还是进入储物柜。
- 立即向出口推进，还是先去更安全的路线重置追捕状态。

### 核心循环

~~~text
观察出口与威胁
    ↓
选择短险 / 中衡 / 长安路线
    ↓
移动、冲刺或保持安静
    ↓
未发现 → 继续推进
被怀疑 → 利用遮挡降警觉
被追逐 → 转角断追 / 藏身
    ↓
到达警局 → 结算 → 改进下一局
~~~

### 优化项

| 优先级 | 优化 | 规则边界 |
|---|---|---|
| P0 | 完整出生保护 | 保护期内禁用感知、追捕移动和抓捕；两个开局方向都不得形成 3 秒必死 |
| P0 | 公平发现与断追 | 视锥、LOS、怀疑时间、最后已知位置、Search |
| P0 | 三条真实路线 | 短而暴露 42–46 格；中等平衡 50–54 格；长而安全 58–64 格 |
| P0 | 储物柜藏身 | 未被目击进入可断追；被目击进入会被检查；不使用隐藏随机概率 |
| P0 | 碰撞与遮挡一致 | 视觉阻挡、玩家碰撞、AI 导航和 LOS 使用同一关卡数据 |
| P0 | 出口方向 | 始终显示离屏方向标记；距离使用最短路径距离 |
| P1 | 短时冲刺与体力 | 冲刺更快但产生更大声音；不增加复杂技能树 |
| P1 | 声音调查 | 冲刺或互动只让 AI 去声源调查，不直接暴露玩家实时位置 |
| P1 | 结算反馈 | 展示时间、发现次数、断追次数、近身险情和路线 |

### 可玩性验收

- 新玩家 10 秒内能指出出口、敌人状态和至少一种断追方式。
- 两个开局方向都不存在 3 秒内强制死亡。
- 被发现到被抓的中位时间为 4–8 秒，至少提供一次反制机会。
- 连续两个拐角可以稳定断追。
- 失败后 2 秒内可重新操作。
- 首次玩家单局中位数达到 60–120 秒。

## 3.2 耐玩性

### 当前问题

- 地图、出生点、出口、巡逻顺序和道具位置完全固定。
- 主要路线近似等长，记住一次路线后最优解基本不变。
- 没有最佳成绩、评级、挑战目标或局后数据。
- 三风格切换只能提供视觉变化，无法替代真正的玩法复玩。

### 耐玩性的四层结构

#### 第一层：技巧成长

玩家通过掌握路线、视线、冲刺时机和藏身规则自然变强，不依赖数值升级。

#### 第二层：局内路线差异

三条路线必须同时有通关价值：

| 路线 | 距离 | 风险 | 资源 |
|---|---:|---|---|
| 短而暴露 | 42–46 格 | 长视线、巡逻覆盖高 | 藏身少，适合竞速 |
| 中等平衡 | 50–54 格 | 视线与拐角平衡 | 1 个可靠断追点 |
| 长而安全 | 58–64 格 | 容易走错、耗时高 | 遮挡多、藏身多 |

#### 第三层：人工验证的局面变体

不生成随机迷宫，只提供 3–5 套设计过的种子：

- 巡逻起点与方向变化。
- 一个软封路点变化。
- 一个储物柜或声音道具位置变化。
- 单局开始后固定，不在游玩中偷偷改路。
- 每个种子至少保留两条可达路线。

#### 第四层：可见目标

- 本地最佳时间。
- A / B / C 或三星评级。
- 未被发现、零藏身、成功断追、极限逃脱等挑战徽章。
- 结算明确告诉玩家下一局可以改善什么。
- Post-VS 可加入不依赖后端的每日固定种子。

### 轻目标的启用条件

只有当公平追逃完成后，首次玩家单局中位数仍低于 60 秒，才加入一个叙事目标：

> 先触发校园报警器，再前往警察出口。

不扩展成多钥匙、多门锁或复杂收集链。

### 耐玩性验收

- 首次通关后主动再玩率不低于 50%。
- 任一路线不超过成功局的 60%。
- 第三次成功的最佳时间相对第一次平均改善 10%–25%。
- 三个种子连续跑 100 次确定性模拟，出口始终可达且 AI 不会卡死。
- 不同种子的最佳策略不完全相同。

## 3.3 难度设计

### 当前问题

当前难度几乎只由距离阈值 7、玩家速度 3.7 和追捕速度 3.4 决定：

- 敌人全向、瞬时、隔墙发现，规则过强且不可读。
- 玩家转向瞬时、速度更快，选对路线后又过于容易。
- 开局陷阱和十几秒纯跑并存，形成二元难度。
- 没有配置层，所有数值散落在主循环。

### 难度原则

1. 难度首先改变敌人的信息能力、反应和搜索，不只改变速度。
2. 不同档位使用相同规则，玩家学到的技巧可以迁移。
3. 连续失败辅助只在局间公开发生，禁止局内瞬移、读心和隐形橡皮筋。
4. 标准档先以可解释、公平为目标，再追求压迫感。

### 标准档初始调参范围

| 参数 | 当前 | 标准档建议 |
|---|---:|---:|
| 玩家基础速度 | 3.7 格/秒 | 1.6–1.8 格/秒 |
| 玩家冲刺速度 | 无 | 2.1–2.3 格/秒，连续约 2.5 秒 |
| 追捕速度比 | 0.919 | 玩家基础速度的 0.90–0.93 |
| 巡逻速度 | 3.4 格/秒 | 0.7–0.9 格/秒 |
| 完整保护期 | 实际不完整 | 1.5 秒 |
| 远距发现 | 7 格全向穿墙 | 7 格、90 度、必须 LOS |
| 怀疑确认 | 瞬时 | 0.7–0.9 秒 |
| 搜索时间 | 无 | 约 4 秒 |
| 抓捕半径 | 0.58 格点距离 | 0.42–0.48 格胶囊距离 |
| 感知更新 | 每帧 | 10 Hz |
| 寻路更新 | 每帧 | 5–8 Hz，路径缓存 |

### 三档难度

| 档位 | 保护期 | 视锥 | 视距 | 怀疑确认 | Search | 追捕速度比 |
|---|---:|---:|---:|---:|---:|---:|
| 轻松 | 2.5 秒 | 75 度 | 5.5 格 | 1.2 秒 | 2.5 秒 | 0.84 |
| 标准 | 1.5 秒 | 90 度 | 7 格 | 0.8 秒 | 4 秒 | 0.92 |
| 挑战 | 1 秒 | 105 度 | 8 格 | 0.45 秒 | 6 秒 | 0.98 |

这些数值是首轮试玩起点，不是最终真值。

### 一局内的张力曲线

| 阶段 | 目标 |
|---|---|
| 0–10 秒 | 安全理解目标和开局路线，不制造无提示死亡 |
| 10–35 秒 | 首次怀疑或远距离威胁，让玩家认识发现规则 |
| 35–75 秒 | 主要追逐与第一次断追，形成全局高潮 |
| 75–105 秒 | 恢复、再次决策或第二次短追逐 |
| 最后 10–20 秒 | 警局声光增强，出口压力与希望同时上升 |

不要求每局机械地走完所有阶段，但禁止全程追逐或全程没有敌人。

### 难度 KPI

- 轻松档首次通关率 75%–90%。
- 标准档首次通关率 50%–70%。
- 挑战档首次通关率 25%–45%。
- 开局 10 秒内失败率不高于 5%。
- 追逐状态占有效局时 25%–45%。
- 90% 试玩者能解释自己为什么被发现或抓到。

## 3.4 机制设计

### 状态模型

~~~text
Game:
Loading → Ready → Countdown → Playing → Won / Caught → Results → Restart

Player:
Idle / Move → Sprint → Hidden → Caught / Escaped

Chaser P0:
SpawnDelay → Patrol → Suspicious → Chase → Search → Patrol

Chaser P1:
InvestigateSound / CheckLocker
~~~

### AI 公平规则

- 远距离发现必须同时满足视距、前向视锥和无遮挡。
- 近距离感知也要做基础遮挡，避免隔墙贴脸发现。
- 怀疑值满后才进入 Chase；状态变化必须有音画提示。
- Chase 只在看见玩家时更新最后已知位置。
- 丢失视野后前往最后已知位置，然后 Search。
- Search 期间不能读取玩家实时坐标。
- 搜索结束才回到 Patrol。
- 敌人信息、镜头构图和 HUD 标记读取相同的可见性状态。

### 最小机制集

| 机制 | 价值 | 当前阶段 |
|---|---|---|
| 转角断视野 | 最基础、无需按钮的可掌握技巧 | P0 |
| 储物柜藏身 | 唯一主动交互，验证场景玩法化 | P0 |
| 路线风险收益 | 让迷宫从路径变成决策 | P0 |
| 短时冲刺 | 用速度换噪声和体力 | P1 |
| 声音调查 | 让玩家用声音误导或冒险 | P1 |
| 报警器目标 | 仅在局长不足时启用 | 条件性 P2 |

### 储物柜规则

- 未被追捕者目击进入时，玩家进入 Hidden。
- 被目击进入时，追捕者会移动到柜体并执行 CheckLocker。
- 停留过久时通过呼吸、柜门轻响或明确提示增加风险。
- 不使用玩家不可见的随机查柜概率。
- 柜体冷却或重复使用惩罚必须可见，避免无限循环。

### 碰撞、胜负和重置

- 玩家、AI 与终点使用有半径的连续碰撞。
- 抓捕和抵达出口同帧发生时，根据扫掠碰撞的实际先后处理。
- 道具碰撞、AI 导航和 LOS 遮挡来自同一份关卡数据。
- 重开只重置模拟状态、路径缓存、怀疑值、体力和输入，不重新下载模型。
- 页面隐藏或失焦时暂停模拟并清空输入。

### 关卡数据

关卡应从硬编码 React 文件迁出，至少包含：

~~~text
walkable
colliders
occluders
interactables
spawnZones
exitZone
patrolRoutes
routeTags
variantSeeds
difficultyOverrides
~~~

### 机制验收

- 隔墙误发现为 0 / 100。
- Search 状态不读取玩家实时位置。
- 目击和未目击进入储物柜的结果均可重复验证。
- 终点与抓捕边界不存在由代码判断顺序造成的随机结果。
- 60Hz 与 120Hz 显示器上的模拟结果一致。

## 3.5 交互体验

### 当前问题

- 键盘和四方向按钮直接写入同一个按键集合，没有统一输入意图层。
- 页面失焦、系统手势、指针移出和 Pointer Cancel 可能留下粘键。
- 控制按钮在非 Playing 状态仍存在，可能提前写入输入。
- 390 像素宽时出口信息被隐藏。
- UI 只显示时间、直线距离和固定模式名，不显示是否被发现、是否已甩脱。
- 当前四方向按钮不支持自然的模拟摇杆控制，横竖屏布局也未独立设计。
- 开局和胜负卡片覆盖大量有效画面。

### 输入方案

| 平台 | 默认操作 | 备选 / 无障碍 |
|---|---|---|
| 桌面 | WASD / 方向键移动，Shift 冲刺，E 互动 | 点击寻路、手柄 Post-VS |
| 手机 | 动态虚拟摇杆加一个情境互动按钮 | 点击寻路模式、四方向兼容模式 |
| 通用 | 所有设备只产生 MoveIntent 与 ActionIntent | 不让 UI 直接修改角色坐标 |

### 输入可靠性

- Blur、Visibility Change、Pointer Cancel、Pointer Up Outside 全部清空输入。
- 使用 Pointer Capture 管理持续按压。
- 仅在 Playing 状态接收移动和互动。
- 暂停、加载和结算期间冻结模拟。
- 控件触摸热区不小于 44 CSS px，推荐 48–56 px。
- 使用 Safe Area 变量适配刘海和 Home Indicator。

### HUD 信息层级

HUD 只回答四个问题：

1. 出口在哪：边缘方向箭头加路径距离。
2. 敌人是否发现我：Patrol、Suspicious、Chase、Search 清楚可读。
3. 我还能否冲刺：简洁体力或冷却提示。
4. 当前是否可互动：只在储物柜等附近显示情境按钮。

时间、最佳成绩和难度保持次级，不覆盖主视野。

### 镜头设计

| 状态 | 构图 |
|---|---|
| Patrol | 玩家前进方向留白，不显示墙后敌人精确位置 |
| Suspicious | 轻微拉远，出现短促提示 |
| Chase | 仅在敌人真实可见时进行双人构图 |
| Search | 回到玩家中心，保留紧张但不泄露坐标 |
| Win / Caught | 短时收紧，服务角色演出 |

实现要求：

- 相机焦点与距离分别阻尼，避免状态切换跳变。
- 墙体使用淡出、切顶或 Dither，不再只靠无限拉远。
- 玩家不得被近墙完全遮挡超过 200ms。
- 竖屏角色屏幕高度不低于约 7%。
- 桌面保留滚轮和 0 重置；手机增加加减按钮或双指缩放。

### 引导与无障碍

- 首次开始用 3 个以内的情境提示，不用长说明卡遮住场景。
- 人物名字与脚环只在新手期短暂出现。
- 提供静音、暂停、减少动态效果和色弱可读配色。
- 支持 prefers-reduced-motion，降低镜头冲击、闪光和脉冲。
- 失败原因使用具体文案，例如“转角后仍在视线中”，而不是只说“换条路线”。

### 交互验收

- 390 × 844 与 844 × 390 都能完整游玩。
- 连续 20 次拖出按钮、切后台、系统手势打断，粘键为 0。
- 出口方向在任何宽高比下都不会消失。
- 镜头不会因墙后敌人明显偏移或拉远。
- 新玩家不阅读外部说明也能在 10 秒内开始有效移动。

## 3.6 美术效果

### 当前问题

- 正式高模已在场景中，但镜头宽、人物小，投入的细节无法被看到。
- 三个角色合计约 42.8 万三角面，没有 LOD。
- 9 套 FBX 动画尚未进入 Web 运行时，人物存在脚滑和程序摆动感。
- 墙体被非等比压成约 2 × 1.12 × 2 米，并填满所有阻挡格，形成大片重复白块。
- 17 类环境道具多为单件陈列，没有组成可信区域。
- 角色挂载点光源会穿墙照明并暴露敌人位置。
- 场景没有真正的环境反射基础，材质的布料、皮革、金属和玻璃层次不足。
- 当前全局光照和曝光偏亮，冷走廊、暖出口与警车红蓝灯的层次没有建立。

### 主风格策略

Vertical Slice 只锁定当前“写实卡通”主风格：

- 角色比例真实但轮廓清楚。
- 材质可信，不追求影视级微表面。
- 环境使用统一的校园材质语言。
- 通过灯光、色温和布景形成区域差异。
- 三风格切换为 Post-VS BLOCKED，不阻塞当前验收。

### 角色表现

- 把现有 9 个 FBX 动画烘焙为一个或少量压缩动画 GLB。
- 使用 AnimationMixer 管理 Idle、Walk、Run、LookAround、Turn、Caught、Celebrate、PointAlert。
- Idle、Walk、Run 之间 0.12–0.2 秒 Cross Fade。
- 90 度以上转向使用转身动作，不瞬间旋转。
- 动画速度匹配实际移动速度，消除脚滑。
- 制作 LOD0 / LOD1 / LOD2；近景保留现有高模，宽镜头使用低模。
- 警察远距离低频更新，胜利演出时恢复完整动画。

### 墙体与区域布景

- 墙只沿可行走格与阻挡格的边界布置。
- 保持源模型比例，不再把墙强制拉成实心方块。
- 只渲染邻接可行走区域的墙。
- Wall、Corner、End、Door 按连接拓扑选择。
- 教室形成桌椅群、黑板、讲台和翻倒路径。
- 走廊形成连续柜组、公告栏、灭火器和散落物。
- 操场形成树、灌木、长椅、篮球架和开放视线。
- 道具既承担区域识别，也承担碰撞、遮挡或叙事。

### 材质、灯光与 VFX

- 先把曝光与全局光强拉回稳定区间，再增加局部效果。
- 移除角色常驻点光，改用受控的轮廓光或材质边缘。
- 加入小型压缩环境反射或 IBL。
- 复用共享 AO / ORM 或材质参数，不为每个道具新增大贴图。
- 金属、玻璃、布料和皮革有清楚但克制的差异。
- 追捕者 Suspicious 使用琥珀提示，Chase 使用短促红色危险层。
- 出口以警局暖光、警车红蓝 Emissive、地面反射和警察剪影共同提示。
- 绿色光柱只保留为首次引导或无障碍层，不作为永久主视觉。
- AO、Bloom 和后处理按高、中、低档启用。

### 美术验收

- 三个角色均使用正式动画，跑步无明显脚滑。
- 教室、走廊和操场能在 2 秒内通过色温和道具组合辨认。
- 墙、门、转角无明显非等比拉伸、悬空和大面积重复白块。
- 玩家和追捕者在桌面与手机镜头中均能快速辨认。
- 警车灯、警局暖光和人物肤色不过曝，暗部仍可识别轮廓。
- 完整效果仍满足 Draw Calls 不高于 150、三角面不高于 100 万和中端手机 30 FPS。

## 3.7 沉浸体验

### 当前问题

- 当前完全静音，追逐、甩脱、接近出口和胜负没有情绪反馈。
- AI 没有怀疑、搜索和最后已知位置，无法形成“险些被发现”的心理节奏。
- 镜头、UI、动画和未来音频没有统一事件源，容易互相矛盾。
- 胜利只是弹窗，警察不上前，追捕者不退场。
- 失败没有抓捕动作、心跳停顿或淡出。
- 道具在开局后继续并发载入，可能突然出现或触发首次材质编译卡顿。
- 当前明亮灰绿色场景与概念稿中的冷暖追逐氛围存在落差。

### 统一感官反馈矩阵

| 状态 | 镜头 / UI | 动画 | 声音 | 灯光 |
|---|---|---|---|---|
| Patrol | 前方留白，无精确敌人标记 | Villain Walk | 校园底噪、远处脚步 | 冷色稳定 |
| Suspicious | 轻微拉远，琥珀提示 | PointAlert | 发现前奏 | 局部轻闪 |
| Chase | 可见时双人构图，红边渐强 | 双方 Run | 发现 Stinger、紧张层、心跳 | 对比略升 |
| Search | 回到玩家中心，不泄露坐标 | LookAround | 脚步和呼吸减弱但不停 | 冷色保留张力 |
| Caught | 短暂收紧后淡出 | ScaredCaught | 心跳停顿、失败音 | 红边峰值后黑场 |
| Win | 警察与玩家近景 | PointAlert / Celebrate | 警笛、胜利 Stinger | 暖色安全区 |

### 音频最小集

- 校园环境底噪。
- 基础音乐层与紧张音乐层。
- 小孩轻脚步和追捕者重脚步。
- 发现提示音与搜索提示音。
- 近距离心跳。
- 警局环境声与警笛方向。
- 胜利和失败 Stinger。

实现要求：

- 第一次点击开始时解锁 WebAudio。
- 提供静音并在本机记住设置。
- 脚步、心跳和警笛按状态与距离混音。
- 墙后只提供模糊方向和音量，不提供精确坐标。
- 使用压缩 Opus / OGG 或等效 Web 格式，避免大体积无压缩音频。

### 环境叙事

- 散落书本、书包、翻倒桌椅说明校园刚发生过追逐。
- 公告栏、黑板和门牌帮助玩家记住区域。
- 远处警笛、红蓝灯扫过墙面和暖色出口形成希望感。
- 灯具轻闪、树叶微动、散纸轻动作为低成本动态。
- 首次游玩可有不超过 3 秒、可跳过的环境引导镜头；复玩跳过。

### 胜负演出

胜利：

1. 玩家进入警局区域。
2. 警察上前并指向安全位置。
3. 追捕者停步、犹豫并退场。
4. 镜头收紧，暖光和警笛完成情绪释放。
5. 显示本局数据、评级和再来一次。

失败：

1. 抓捕动作与危险反馈到达峰值。
2. 心跳短暂停顿，播放失败音。
3. 画面快速淡出。
4. 2 秒内恢复到可操作状态。

### 沉浸验收

- 关闭 HUD 后，至少 4 / 5 名试玩者仍能判断追逐开始与已经甩脱。
- 发现、搜索、胜负时镜头、动画、声音、UI 和灯光状态不矛盾。
- 一局中没有可见道具硬弹出或首次材质编译造成的明显卡顿。
- 未获得用户手势前不触发自动播放错误。
- 胜利不再只是弹窗，失败到重新操作不超过 2 秒。

## 4. 跨领域技术基座

七个体验维度必须共用以下基础，否则会反复返工。

### 4.1 模块边界

~~~text
game/
├─ config/          难度、关卡、资源与设备档
├─ simulation/      固定步长、状态、胜负与重开
├─ navigation/      网格、路径、LOS 与路径缓存
├─ ai/              追捕者 FSM、感知、搜索和声音调查
├─ input/           Keyboard、Pointer、Joystick、Tap-to-move → Intent
├─ renderer/        Three.js 场景、角色、相机、灯光与遮挡
├─ animation/       AnimationMixer、状态混合与重定向
├─ audio/           音乐层、脚步、心跳、警笛与 Stinger
├─ ui/              HUD、引导、暂停、结果和无障碍
├─ assets/          Manifest、加载、缓存、压缩与释放
└─ qa/              指标、事件记录和运行态测试接口
~~~

React 只管理页面容器、HUD 和菜单，不承载整套模拟循环。

### 4.2 模拟与事件

- 逻辑固定 60Hz。
- AI 感知 10Hz。
- 寻路 5–8Hz，目标格或状态变化时立即刷新。
- 渲染根据模拟快照插值。
- 所有表现订阅统一事件，不自行推断危险。

首批事件：

~~~text
game_started
player_spotted
suspicion_cleared
chase_started
sight_lost
search_started
search_ended
hide_entered
hide_revealed
exit_near
player_caught
player_escaped
game_restarted
~~~

### 4.3 自动化测试

单元测试：

- 地图可达性与三条路线长度。
- 出生保护期间禁止感知、移动和抓捕。
- 视锥、LOS、近身感知与墙体遮挡。
- Patrol → Suspicious → Chase → Search → Patrol。
- Search 不读取玩家实时位置。
- 储物柜目击与未目击结果。
- 抓捕与出口同帧的事件顺序。
- 重开清理状态、路径缓存、体力和输入。
- 三个种子和三档难度的确定性结果。

运行态测试：

- Kid、Villain、Police 与必需 GLB 加载成功。
- 桌面键盘、手机摇杆、点击寻路和互动。
- 390 × 844、844 × 390 与桌面宽屏。
- 失焦、切后台、Pointer Cancel 和恢复。
- Draw Calls、三角面、首玩资源、帧率与内存。
- WebGL Context Lost 后可恢复。
- 20 次连续胜负和重开无角色、事件或 GPU 资源泄漏。

### 4.4 轻量 QA 记录

本地记录以下匿名局内数据，不需要账号或后端：

- 难度与关卡种子。
- 选择路线。
- 首次发现时间。
- 追逐总时长。
- 断追次数。
- 藏身次数。
- 失败位置与失败原因。
- 通关时间与重开行为。

这些数据用于调参，不作为在线分析系统的前置依赖。

## 6. 统一 KPI 看板

首轮目标由 5–12 名新玩家试玩校准，之后再扩大样本。

| 维度 | 核心 KPI |

## 7. 试玩与验收方法

### 7.1 样本分组

- 5–8 名从未玩过的新玩家。
- 3–4 名已经知道规则的熟练玩家。
- 至少 2 台桌面浏览器和 2 台手机真机。

### 7.2 新玩家测试

不先解释玩法，只观察：

- 多久理解出口方向。
- 是否知道敌人已发现自己。
- 第一次失败后能否说出原因。
- 是否主动使用转角或储物柜。
- 通关后是否愿意立即再玩。

### 7.3 熟练玩家测试

观察：

- 是否出现唯一最优路线。
- 是否能滥用储物柜或转角让 AI 失效。
- 挑战档是否仍然公平。
- 三个种子是否要求不同策略。
- 竞速是否依赖技巧而非随机运气。

### 7.4 设备矩阵

- macOS Chrome 当前版。
- macOS Safari 当前版。
- iPhone Safari 真机。
- Android Chrome 真机或等效设备。
- 桌面常见宽屏。
- 390 × 844 竖屏。
- 844 × 390 横屏。

## 8. 主要风险与降级策略

| 风险 | 影响 | 处理 |
|---|---|---|

- 不提交历史候选、拒稿、重复导出与备份。

- 复用现有 29 个 GLB、9 套动画和共享材质。
- 新音频使用压缩格式。
- 三风格资产未来按需下载，不同时进入首玩阻塞包。

## 9. Vertical Slice 总验收

### 9.1 可玩与公平

- [ ] 开局没有无提示必死路线。
- [ ] 敌人不会隔墙远距离发现玩家。
- [ ] 玩家可以通过转角或储物柜稳定断追。
- [ ] 至少两条路线具有真实通关价值。
- [ ] 失败后 2 秒内重新操作。

### 9.2 难度与复玩

- [ ] 三档难度使用相同规则且达到目标通关率。
- [ ] 新手中位局长 60–120 秒。
- [ ] 熟练玩家能进入 30–60 秒竞速区间。
- [ ] 本地最佳、评级、局后数据与三个种子可用。
- [ ] 首次通关后再玩率不低于 50%。

### 9.3 交互

- [ ] 桌面、手机竖屏和手机横屏均完整可玩。
- [ ] 出口方向、敌人状态和互动提示始终可读。
- [ ] 失焦、切后台和指针中断不会粘键。
- [ ] 墙后敌人不会通过标签或镜头泄露精确位置。
- [ ] 暂停、静音和减少动态效果可用。

### 9.4 美术与沉浸

- [ ] 三角色使用正式动画，无明显脚滑。
- [ ] 教室、走廊和操场具有清楚的视觉身份。
- [ ] 墙体不再形成大片厚重白块。
- [ ] Chase、Search、出口临近、胜利和失败均有一致音画反馈。
- [ ] 胜利表现警察保护，失败具有抓捕和快速恢复。

### 9.5 性能与稳定性

- [ ] Draw Calls 不高于 150。
- [ ] 三角面不高于 100 万。
- [ ] 首玩阻塞资源不高于 12 MiB。
- [ ] 中端手机不低于 30 FPS，目标设备尽量 60 FPS。
- [ ] 20 次重开无持续内存增长。
- [ ] 资源失败、WebGL Context Lost 和弱网均可恢复。

五组全部通过，才能把版本标记为“第一关可验收”。任何单一维度的高分都不能替代完整闭环。

## 10. Post-VS 路线

只有 Vertical Slice 通过后再评估：

- 三套美术风格重新制作、按需下载与运行时切换。
