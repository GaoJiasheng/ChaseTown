## 1. 基线能力与真正缺口

本节只描述页首 Git commit 的能力快照，不充当当前 HEAD 或线上版本事实。长期规划必须从这份可追溯基线出发，避免重复建设；后续能力变化应进入与 commit 绑定的发布 manifest，不持续改写本节。

| 领域 | 已有能力 | 长期缺口 |
| --- | --- | --- |
| 核心玩法 | 固定镜头移动、追逐、断视线、最后目击点、巡视、搜索、躲藏、逃生；已有捕获原因与行动建议 | 玩家主要仍在“走位和等时机”；失败反馈还不是可复核的证据时间线 |
| 躲藏 | 硬柜、软遮挡、穿越式藏点三类规则与公平性合同 | 三类藏点需要更强的专属模型、动画、音频、重复使用痕迹和真正不同的局内决策 |
| 关卡 | 10 关主题战役、复杂迷宫、主题任务、30 个认证 Remix | 当前准备任务最终汇合到单一出口；缺少真正互斥的计划、双出口和可持续内容生产工具 |
| AI | 单追捕者的合法视觉/声音证据账本、三证据上限、同源习惯化与确定性状态机 | 缺少便携诱饵完整因果链、区域级记忆和可理解的双敌人协作协议 |
| 主题机制 | 校园、医院、消防站、工厂各有主动机关、代价和合法声音证据 | 缺少跨系统组合、便携诱饵、可逆世界状态和局内资源选择 |
| 复玩 | 精通、成绩、语义 Ghost、本地进度、认证 Remix | 缺少长期合同、好友异步挑战、可选云档和经过验证的线上复玩层 |
| 美术音频 | 正式角色、PBR 环境、英雄柜、主题 Foley、自适应音乐和可复现资产管线 | 新互动的英雄级资产、动作、声画反馈必须跟玩法同时生产，不能先上线功能再补皮肤 |
| Web 工程 | 确定性模拟、资源预算、KTX2、LOD、三档质量、完整自动回归、双 clean build 与 release-integrity CI | 主场景编排仍集中在约 8,700 行文件；主包、首局资源、真机矩阵、浏览器视觉 CI、遥测和发布运维余量不足 |

因此，下一阶段的主线不是立刻增加第 11–20 关，而是把现有十关背后的潜行语法做深，并建立能够低风险扩产的内容与平台能力。

## 2. 长期产品定位

### 2.1 一句话愿景

把《追逐》做成一款“玩家读懂危险、操纵环境、制造错误判断、承担代价并完成脱身”的高品质 Web 3D 系统性潜行逃生游戏。

### 2.2 一局的理想体验

一局不应只有“找到最短路线并跑得更准”，而应稳定产生以下节奏：

1. **观察**：从灯光、脚步、无线电、门体和敌人动作判断局势。
2. **选择计划**：在安静长路、危险捷径和主动误导之间作出承诺。
3. **制造机会**：关闭一组灯、制造一条声音证据、改变门或视线状态。
4. **承担代价**：操作耗时、产生噪声、消耗有限道具或暴露一段时间。
5. **脱离追逐**：切断视线、改变路线或进入适合当前风险的藏点。
6. **读懂搜索**：通过敌人可见表演判断其掌握了什么，而非猜测全知 AI。
7. **兑现路线**：完成分支目标，从合适出口离开，并理解自己的成绩为何成立。

### 2.3 五条长期支柱

1. **公平但不迟钝**：敌人可以聪明、协作和施压，但只能消费可证明的公开证据。
2. **系统而非脚本答案**：灯光、声音、门、藏点、任务和 AI 证据能够组合，不为每个场景写唯一解。
3. **每次行动都有成本**：强工具不能是无脑按钮；必须有时间、噪声、暴露、资源或路线成本。
4. **运行画面即成品**：玩家可见版本不出现线框、简单几何人偶、临时音效或无动作机关。
5. **低门槛、高精通**：浏览器打开即可玩，第一局可理解，长期由路线、判断和执行产生深度，不靠数值碾压。

### 2.4 目标玩家与时长

- 主要玩家：喜欢短局潜行、追逐压力、空间解谜和“失败后立刻再来一次”的玩家。
- 次要玩家：追求成绩、精通和 Ghost 对抗的速通玩家，以及只用手机浏览器体验一小局的轻量玩家。
- 单关首次通关目标 4–7 分钟，精通复跑目标 1–3 分钟；一次典型会话由约 3 份合同构成，总时长 12–20 分钟。
- 游戏不要求长期刷装备，也不依赖每天登录；离线单机闭环始终完整。

## 3. 北极星指标与 18 个月成果

### 3.1 北极星指标

长期北极星定义为：

> **Q7：完成一次 Standard 关卡后，7 天内回来启动另一份认证合同的玩家比例。**

选择 Q7 的原因是：它同时检验核心玩法是否值得复玩、合同是否清楚、内容是否有变化、加载是否足够轻，以及玩家是否愿意继续精通。M0–2 先建立真实基线；M2–M11 把 Q7 作为组合健康指标，每阶段报告但不把混合内容变化归因给单一功能。只有 M11 的冻结对照试验把 Q7 用作因果 Gate。18 个月总目标为相对基线提升至少 50% 或绝对提升至少 4 个百分点，二者先达到者为准。

Q7 不能单独驱动设计。不得通过强制签到、冗长解锁或隐藏内容来虚增回访。

Q7 的唯一统计口径：

- **身份**：首次同意产品遥测时生成随机、第一方、可撤销的 `anonymousInstallId`，只保存在当前浏览器站点存储中；不得用指纹、IP 或硬件特征补全。
- **分母**：UTC 自然日内首次完成任意 Standard 的有效安装 ID，每个安装每个候选版本只进入一次 cohort。
- **分子**：同一安装 ID 在完成时刻 24 小时后、168 小时内，启动 `contractId` 不同的另一份认证合同。
- **认证合同**：Standard、官方 Remix 或官方周合同；重开同一关、Debug、自动 QA、内部 preview 和机器人流量不计。
- **重置边界**：清站点数据或重装浏览器视为新安装；多设备分别计数；只有未来明确同意的账号云档才能合并。
- **拒绝遥测**：不进入远程 Q7 分母；本地游戏继续完整可玩。报告必须同时披露同意覆盖率，防止把选择偏差伪装成全体玩家。
- **时区与迟到事件**：cohort 固定按 UTC，允许 24 小时迟到窗口；超窗数据进入审计但不回写已经冻结的阶段结论。

### 3.2 产品成果

18 个月结束时，目标状态是：

- 十关均使用同一套成熟的潜行语言，但每个主题至少有一个不可替代的环境规则。
- 至少 8/10 关拥有两种真正不同的任务计划或两个有效出口；另外两关可以为教学或终局保持更强编排。
- 每关至少支持“低暴露潜行、主动误导、快速高风险”三种可完成风格，不存在唯一策略长期占比超过 60%。
- 三类藏点均有专属正式 3D 资产、交互动作、声音和可理解的风险；不是换标签的同一柜子。
- 至少一个章节完成双敌人验证；双方通过有延迟、有精度损失的证据包协作，不共享隐藏玩家实时位置。
- Standard、Remix、精通、周合同和 Ghost 形成一个水平复玩体系；解锁不增加玩家速度、隐身值或敌人削弱。
- 在核心指标全部达标后，M18 才决定是否启动一个新主题章节；新主题生产属于下一规划周期，不与十关收口并行承诺。

### 3.3 体验指标

| 指标 | 目标区间 | 解释 |
| --- | ---: | --- |
| 第一关首次尝试通关率 | 35%–65% | 低于区间说明教学或可读性不足；过高说明没有压力 |
| 第一关三次内通关率 | 70%–85% | 保证新玩家能通过学习取得进展 |
| 失败后立即重试率 | ≥60% | 失败必须让人觉得“我知道下一次怎么改” |
| 能解释被抓原因的玩家 | ≥85% | 通过问卷、回放原因和行为证据联合判断 |
| “AI 不公平”主观反馈 | ≤5% | 任何信息泄漏自动化用例仍要求 0 |
| 单次通关有效潜行决策 | 平均 ≥2 次 | 机关、诱饵、藏点、换路需实际改变风险 |
| 熟练玩家单一路线占比 | ≤60% | 防止所有系统最后仍收敛到唯一答案 |
| 通关后继续第二局 | ≥35% | 判断短期复玩价值 |
| Remix 尝试率 | ≥35% | 只统计已解锁且真正启动的玩家 |
| 二次精通尝试率 | ≥20% | 判断评价和 Ghost 是否形成目标 |

这些是决策门槛，不是对当前版本成绩的宣称。统一样本规则为：

- “熟练玩家”指同一候选规则集已完成至少 3 局 Standard 的有效安装 ID。
- Gold Standard 产品 Gate 至少需要 100 个同意遥测的独立安装、300 局有效外测；路线占比至少需要 30 名熟练玩家。
- “能解释被抓原因 / AI 不公平”至少需要 50 名不同玩家、100 次有效被抓后的单次问卷，单一玩家在一个候选版本中只计一次同类回答。
- 每个候选观察窗口至少连续 14 天；重大规则变更会开启新窗口，不能拼接前后版本凑样本。
- 内部员工、自动回放、无效回放、未完成加载、少于 20 秒的误触局和重复机器人流量不计。
- 样本不足时，工程/美术可以继续完善黄金样板，但产品 Gate 保持 `INSUFFICIENT_DATA`，不得迁移 Wave B 或宣称指标通过。

## 4. 所有新机制必须遵守的合同

任何功能进入正式生产前，必须有一页完整机制合同，至少回答：

1. **玩家意图**：它帮助玩家做什么新判断，而不是只增加一个按钮。
2. **触发与边界**：何时可用、何时不可用、能否取消、是否可重试。
3. **明确成本**：时间、声音、暴露、数量、路线或机会成本至少一项。
4. **敌人证据**：AI 能得到什么、精度多少、何时衰减；禁止直接读玩家状态。
5. **敌人反制**：重复滥用后敌人如何基于合法证据调整，而非偷偷免疫。
6. **玩家反馈**：模型、动作、灯光、声音、震动、字幕和 HUD 如何表达同一状态。
7. **失败解释**：玩家如何知道是哪里判断错，而不是只看到“被抓”。
8. **无障碍替代**：不能把颜色、立体声、震动或快速连按作为唯一信息通道。
9. **性能预算**：模型、贴图、动画、音频、draw call、粒子和运行成本。
10. **验证证据**：确定性测试、AI 信息隔离、浏览器冒烟、真机、截图和人工体验验收。

合同不完整时可以做只存在于非发布工具中的逻辑试验，但不能进入玩家可见候选版。玩家可见的动画和美术原型从第一次评审起就使用批准资产，不用几何块“以后再换”。

## 5. 系统性潜行 2.0

### 5.1 环境操纵与误导

现有四类主题机关继续作为基础层，下一步不是简单增加更多按钮，而是建立“改变世界状态 → 生成公开证据 → 影响敌人判断 → 玩家利用窗口”的组合。

| 能力 | 优先级 | 设计价值 | 成本与限制 | AI 公平边界 |
| --- | --- | --- | --- | --- |
| 有限声音诱饵 | P0 Core | 把现有声音证据/习惯化扩展为玩家可携带的完整误导链 | 每局 1–2 次；投掷/放置有动作和落点声；同源重复会习惯化 | AI 只收到带误差声源，不知道投掷者后续位置 |
| 分区电闸与灯路 | P0 Gate 2 | 改变可见性、路线可读性和摄像头状态 | 操作需承诺时间；断电区也降低玩家信息；恢复电源会产生明显事件 | 只修改合法视觉采样与公开世界状态，不改抓捕距离 |
| 摄像头与保安终端 | Stretch | 用有限信息换路线判断 | 站在终端时无法移动；只显示有摄像头覆盖的延迟画面 | 不在 HUD 中持续透视敌人；画面有覆盖、延迟和盲区 |
| 门锁、卷帘与临时路障 | P1 | 让玩家短时改变追逐拓扑 | 开关门有时间和声音；敌人可绕行或用正式动作处理 | 路径变化对双方可见；不得凭空封死唯一逃生路 |
| 广播、电话与控制台 | P1 | 产生强证据并组合主题声景 | 固定位置、冷却长、使用时暴露 | 证据带来源身份，敌人可因重复使用降低置信度 |
| 可移动遮挡 | P2 | 允许玩家预先塑造视线 | 只在少数英雄场景使用；移动慢、有噪声、性能成本高 | 必须先通过碰撞、导航重建和移动端预算，不做全场物理沙盒 |

首轮严格串行：先闭合“投放诱饵 → 生成证据 → AI 合法调查 → 玩家利用窗口”的单一因果链；通过理解率、公平性和性能验证后，才加入分区电闸。摄像头/终端是 Stretch，只有前两项已经产生两种有效路线且仍有资产与性能余量时才进入 Gold。P1 必须等待 Gold 全部门禁。

### 5.2 真正的分支目标与双出口

当前任务允许两项准备任意排序，但最终仍要求全部完成并汇合到一个出口。长期方案把它升级为“计划不同，风险结构也不同”：

- **授权路线**：寻找凭证或使用终端；操作更久、路线更安静，最终出口较安全。
- **维护路线**：操作电闸、旁通阀或机械释放；噪声更强、路程更短，出口暴露更大。
- **可选目标**：救援、取证、关闭危险源或回收档案，只影响精通、叙事和合同，不增加永久战力。
- **双出口**：两个出口都必须从开局可理解，但各自的解锁条件、末段构图和敌人覆盖不同。

设计红线：

- 选择某条路线后允许付出成本改道，不能因一次误操作永久软锁。
- 必要交互均可重试，不消耗唯一任务物品，不关闭另一项必要目标的唯一通路。
- 双出口不是“同一扇门换位置”；至少在任务成本、末段追逐或信息条件上有两项差异。
- 每关最多两个主要计划和一个可选目标，避免 HUD 变成任务清单。

### 5.3 躲藏 2.0

三类藏点保留统一证据合同，但形成清晰战术三角：

| 类型 | 强项 | 弱项 | 需要补齐的正式表现 |
| --- | --- | --- | --- |
| 硬质藏柜 | 完全遮蔽、可窥视、等待风险低 | 进出较慢、门声清楚、被目击后检查风险高 | 主题化柜体、门锁与百叶差异，完整手部接触和内部声场 |
| 软质遮挡 | 进入快、声音轻、适合紧急脱离 | 只是部分遮挡，长时间占用会产生可见扰动 | 桌下、帘后、器材罩等专属姿态与布料/碰撞动画 |
| 穿越式藏点 | 能从另一侧离开、改变追逐路线 | 两端都有动静、离开风险高 | 通风/维护通道、长柜或设备夹层的连续穿行动作与双端声画 |

深化规则：

- 重复使用同一藏点只能通过公开痕迹提高搜索吸引力，例如门未完全复位、布帘摆动或连续声音；AI 仍不得读取占用状态。
- 快速离开与谨慎离开可以有不同时间/声音成本，但不做强制节奏 QTE。
- 窥视越频繁，视觉暴露和门体扰动越容易被观察；反馈必须在画面上先于规则生效。
- 敌人检查不同藏点必须有专属动作和持续时间，不能统一走到坐标后瞬间结算。
- 呼吸、心跳和狭窄镜头负责营造压力，不作为没有替代提示的隐藏数值惩罚。

### 5.4 双敌人协作

双敌人是中期能力，不在基础潜行稳定前提前铺到十关。

首个组合只做两个角色：

- **追踪者 Hunter**：保持视觉压力、前往最后目击点、迫使玩家移动。
- **封路者 Interceptor**：根据收到的低精度证据占据公开岔路或调查次级声源，不直接追踪隐藏玩家。

共享协议必须满足：

- 只传递发送时刻的证据快照：类型、位置误差、置信度、时间戳和来源。
- 无线电/手势带 0.8–1.5 秒可见延迟；接收后还要导航，不能瞬移或瞬时转向。
- 证据会过期和降精度；任何敌人都看不到“玩家当前藏在哪个柜子”。
- 角色用无线电、目光、手势和路线动作预告协作，玩家能看懂“为什么另一人来这里”。
- 路线预约避免两敌人互相堵塞，也避免长期无解地封死全部出口。
- Standard 首次只在一个示范章节启用双敌人；数据达标后再扩展，最高同时活跃数仍保持 2。

### 5.5 种子化事件导演

事件导演负责让同一关产生变化，但不负责作弊制造难度。

- 所有事件由版本化 seed、房间标签、玩家已完成动作和威胁预算决定，可完整回放。
- 事件必须在发生前由灯光、广播、机械预热或环境声明确预告。
- 导演可以调度停电、门体循环、烟雾、机器噪声和巡逻换班，但不能在镜头外生成敌人、读取藏身位置或关闭唯一可行路线。
- 同一时刻只允许一个主要事件和一个次级环境事件，避免信息噪声。
- 每关必须有“无导演事件也可通关”的验证路径；事件增加决策，不成为随机过关税。

该系统在双敌人协议稳定后进入单关试点。若两轮测试仍让玩家难以解释失败，则保留为认证合同修饰器，不进入 Standard 战役。

### 5.6 难度与辅助规则

难度来自同时阅读和组合已经学会的规则，不来自敌人作弊：

- 第一幕一次只教学一个主动系统；第二幕要求把藏点与机关组合；第三幕加入协作敌人；第四幕才组合事件导演与高压路线。
- Standard 可以调整确认时间、证据衰减、搜索覆盖、协作延迟和资源数量，但不能扩大到隔墙感知、读取占用状态或瞬时封路。
- 辅助规则与 Standard 分轨保存，允许延长预警、增强非空间提示、降低操作承诺或提供路线帮助；不得用贬义标签，也不影响内容解锁。
- 认证合同负责额外挑战，例如有限藏点、单次诱饵或更紧目标时间；不能悄悄改变基础公平规则。
- 相邻关首次通关率下降超过 12 个百分点时，先检查教学、可读性和空间结构，再调速度。
- 每次平衡修改同时审查新手、普通、熟练和速通四类策略，防止只优化平均值。

### 5.7 交互、叙事与沉浸

- 保持“移动 + 单一上下文互动 + 按住观察”的低输入复杂度；便携诱饵也优先复用上下文选择，不扩成多按钮技能栏。
- 交互提示同时提供动作、代价和状态，例如“切断灯路 · 需要 2 秒 · 会触发备用灯”，而不是只写“按 E”。
- 关键信息至少有两种通道：颜色配图形、声音配字幕/震动、空间方向配宽泛文本。
- 每关用 1–2 个可选环境故事点补充封锁原因、此前发生的事件和安全出口逻辑；单次阅读/观察不超过约 10 秒，不打断追逃。
- 四个主题形成连续小叙事：校园建立规则，医院展示系统失控，消防站引入协作压力，工厂完成高压收束。
- 叙事主要通过场景状态、道具摆放、广播和角色表演传达，不用长过场掩盖玩法薄弱。
- 胜负演出必须回应玩家选择的计划和出口；从不同路线逃生不能只替换结果文案。

## 6. 黄金样板：封馆图书楼

长期系统先在第 2 关“封馆图书楼”做成一个完整 Gold Standard，而不是同时浅改十关。

### 6.1 三种路线

1. **书库潜行线**：高书架、软遮挡和灯路盲区较多；路程长但证据少。
2. **中庭高速线**：距离短、视线长；依靠灯路、门和准确移动承担高暴露风险。
3. **后勤误导线**：经过档案与装卸通道；利用声音诱饵和穿越藏点改变敌人搜索方向。

### 6.2 两个主要计划

- **门禁授权**：在借阅台取得临时权限并到保安终端写入授权，从正门离开。
- **消防释放**：恢复走廊铃电后手动释放后勤消防门，从装卸侧离开。

两条计划都可重试，可以在中途改道，但改道会增加时间和暴露。地图档案作为可选目标，只影响精通和叙事。

### 6.3 首轮正式资产包

- Core 资产：声音诱饵、分区配电箱、门禁读卡器、消防释放机构；保安终端仅承担授权交互。
- Stretch 资产：可观察延迟画面的摄像头和监控终端；未通过 Gate 2 时不进入玩家可见构建。
- 正式声音诱饵及投掷/放置动作，不使用漂浮图标或发光几何球。
- 图书馆专属软遮挡和穿越藏点，各自具备角色接触、物件动作和声音。
- 两个出口的独立门体、灯光、音效和逃生演出。
- 图书馆专属环境故事簇：归还区、档案修复桌、夜间保安点和装卸区。
- 探索、怀疑、追逐三层主题音乐或可连续扩展的同拍 stem；互动 Foley 有来源、响度和字幕替代。

### 6.4 Gold Standard 退出门槛

- 三种路线均由真实玩家完成，熟练玩家任何单一路线占比不超过 60%。
- 两个计划各自被至少 25% 的完成局采用；其余允许为中途改道。
- 完成局平均出现至少两次有效潜行决策，不以单次机关点击充数。
- “AI 不公平”反馈 ≤5%，自动化信息隔离违规为 0。
- 失败后重试率 ≥60%，玩家能准确描述至少一项下次可改进的行为。
- 所有互动在桌面、竖屏和横屏均有正式模型、动作、音频、字幕与状态反馈。
- 首局关键传输必须通过当期构建资产预算门禁，并向 6.5 MiB 长期目标收敛；路线图不复制当期硬阈值。
- 同一候选版本通过确定性、回放、资源、视觉、真机、无障碍和发布回归。

只有黄金样板达到退出门槛，才允许把机制迁移到其余九关。

### 6.5 顺序闸门与砍需求顺序

1. **G1 误导闭环**：只加入便携诱饵和一条可利用路线；先验证玩家是否理解证据、AI 是否公平、误导是否真正改变选择。
2. **G2 计划分化**：G1 通过后加入分区电闸、第二计划和第二出口；验证路线分布与重试率。
3. **可选 G3 信息工具**：G2 通过且资源/性能有余量后，才加入延迟摄像头；单独观察它是否改善计划判断，而非只提高成功率。
4. **G4 成品收口**：冻结 `GoldScopeManifest`，明确 G3 为 included 或 rejected，再完成三类藏点、两出口、主题环境、动画、音乐、字幕和移动端最终精修。

| Gate | 最低有效样本与窗口 | 晋级门槛 | 失败动作 |
| --- | --- | --- | --- |
| G1 | ≥20 个独立外测安装、≥40 局有效诱饵局、同一规则连续 7 天 | ≥80% 能解释诱饵为何改变调查；≥50% 有效投放同时改变 AI 调查目标和玩家路线；不公平反馈 ≤5%；信息隔离违规 0；性能门禁通过 | 返工一次；连续两轮未过则移除便携诱饵，不进入 G2 |
| G2 | ≥30 个独立外测安装、≥80 局有效双计划局、同一规则连续 7 天 | 两计划各自启动占比 ≥20%；软锁 0；失败后重试 ≥55%；熟练玩家单一计划占比 <70% | 修路线/成本后重测；连续两轮未过则退回非 Gold 基线，不迁移 Wave B |
| 可选 G3 | ≥20 个独立外测安装、≥40 局终端可用局、同一规则连续 7 天 | ≥70% 使用者理解延迟与盲区；≥30% 合格局主动使用；≥50% 使用后发生可解释的计划/路线变化；信息过载反馈 <10%；性能通过 | 直接标记 `REJECTED` 并从 Gold scope 删除，不阻塞 G4 |
| G4 | 第 3.3 节完整 Gold 样本：≥100 安装、≥300 局、连续 14 天 | 第 6.4 节全部体验/质量门槛通过，且 scope manifest、规则版本和证据一致 | 保持 Gold 返工；不得开始 Wave B |

发生超期或指标不清时，依次砍掉摄像头、可选档案目标和证据时间线的非关键演出；不得砍掉双计划/双出口、公平证据、正式资产、最小字幕/替代提示或真机质量。已有失败原因与行动建议只升级为证据时间线，不重新实现一套平行系统。

## 7. 十关内容改造顺序

内容采用四波迁移，避免十关同时施工导致质量失控。

退出门槛：

- 黄金样板第 6.4 节全部通过。
- 失败后重试率 ≥60%；平均每个完成局 ≥2 次有效潜行决策。
- 熟练玩家无单一策略占比 >60%。
- 首屏 JS ≤150 KB gzip、进入首关前 JS ≤300 KB gzip。
- 首局关键传输目标 ≤6.5 MiB、全部首关预取目标 ≤7.5 MiB。

### M5–8：战役结构与内容数据化（2027-01 至 2027-03）

必交付：

- 将关卡迁移为版本化 `LevelPackage`，内容包含导航、碰撞、藏点、任务、机关、灯光、音频和资产依赖。
- 建立最小 Blender 语义节点规范、导出器、Web 预览器和自动 KTX2/LOD/缩略图/报告。
- 先完成 Wave B 的 1 暮色放学路与 3 夜间实验翼，重写前四关教学递进所需的公共规则。
- 重新组织十关为四幕，建立主题奖章、战役结局和认证周合同模板。
- 自动平衡农场先覆盖 Gold 与已迁移关的布局 × 规则 × 策略 × seed。

条件性交付：

- 只有内容管线在两关连续无需核心运行时专项修改，才迁移 4 午夜门诊并完成整套 Wave B。
- 高级 Web 编辑器、全十关平衡农场和额外主题奖章演出可以延后，不阻塞 Schema 与两关迁移。

退出门槛：

- 新关卡或变体无需修改核心运行时代码。
- 内容导入到内部可玩预览 ≤30 分钟；不可部署的布局 blockout ≤1 天；使用已批准模块完成一关基础陈设目标 ≤5 个工作日，不包含新英雄资产、独立 Lookdev 与最终美术精修。
- 第一关通关者的战役完成率 ≥30%，相邻关通关率下降不超过 12 个百分点。
- Remix 尝试率 ≥35%，二次精通尝试率 ≥20%。
- 单位、pivot、texel density、材质、LOD、动画 marker、碰撞和导航全部有机器门禁。
- 产品指标至少基于 100 个独立同意安装、300 局有效战役局和连续 14 天稳定候选；不足时状态为 `INSUFFICIENT_DATA`，不得把条件性 Wave B 项升级为完成。

### M8–11：双敌人与高压章节（2027-04 至 2027-06）

主要交付：

- 只在一个满足宽回环、至少两条逃生阀和任务目标预留的 Wave C 代表关完成 Hunter + Interceptor 示范。
- 先完成多 Actor 导航宽度、路线预约、出口封锁上限、抓捕互斥和确定性状态序列的前置审计。
- 实现延迟、降精度、可衰减的证据包通信和可见无线电表演。
- 完成路线预约、封路上限和双敌人回放确定性。
- 只完成该代表关所需的正式 3D 美术、动作、双角色音频层与真机优化；其余 Wave C 关卡在闸门通过后顺延。
- 本阶段不实现事件导演；只冻结其输入边界，避免与尚未稳定的双 AI 同时归因。

退出门槛：

- 单关继续试验阈值：解释率 ≥80%、“不公平”反馈 ≤8%、Standard 通关率 30%–55%、失败后重试 ≥55%。
- 扩散到其他关卡的阈值必须回到全局标准：解释率 ≥85%、“不公平”反馈 ≤5%、失败后重试 ≥60%。
- 两敌人非法共享隐藏信息为 0；受支持重放终态 hash 100% 一致。
- 中端移动 P95 ≤22 ms，低端移动 P95 ≤33 ms。
- 最低样本为 50 个独立同意安装、150 局有效双敌人局、连续 14 天，以及第 3.3 节规定的 50 人 / 100 次被抓问卷；不足时只保留单关试验，不得扩散。
- 若单关继续试验阈值连续两轮失败，双敌人退回单关演出或禁用；达到试验阈值但未达全局阈值时仍不得扩散。

### M11–14：异步复玩与可选在线层（2027-07 至 2027-09）

核心试点：

- 在本地 Ghost 和认证 Remix 上增加无需账号的签名挑战链接。
- 建立最小服务端回放复验、无效回放隔离、滥用举报与数据保留规则；不先建设好友关系、云档或公开榜单。
- 游戏继续支持无账号、本地离线运行；水平解锁不依赖服务器。
- 水平解锁只包含服装、档案、音乐、场景陈列和合同展示。
- 在 Gold 最小无障碍基础上扩展按键重映射、Gamepad、完整字幕、单声道/方向替代、色觉预设和非画布状态摘要，并执行外部审计。
- 把 M0 最小发布健康扩展为自动灰度、完整 SLO、告警和一键回滚。
- 双 AI 已通过且有独立产能时，事件导演可以作为单关 Stretch；它不与社交试点共用成功指标。
- 独立内容 lane 在双 AI Gate 后迁移其余 Wave C；若人员不足则延长总时间，不挤占社交验证或降低美术门槛。
- 挑战链接因果测试使用版本化 50/50 随机 treatment / holdout，以较小总样本获得足够功效；生产内容、规则和引导至少冻结 21 天（14 天入组 + 7 天 Q7 追踪）。导演或 Wave C 可以并行制作，但不得部署进该窗口。

退出门槛：

- 300 个合格同意安装只作为埋点、漏斗和回放质量的最低样本，不是 Q7 因果结论样本。
- 试验前用当时基线 Q7 `p0`、最小有效提升 `MDE = max(3 个百分点, p0 × 10%)`、双侧 `α=0.05`、power `=0.80` 和 50/50 分配，预注册两比例检验所需总样本；未达到该样本量时状态为 `INSUFFICIENT_DATA`。
- treatment 至少产生 100 次有效链接打开；不足时只能判断漏斗未建立，不能评价 Q7 效果。
- Standard 通关者挑战链接参与率 ≥25%，挑战失败后二次挑战 ≥30%。
- 分享链接打开率 ≥20%，无效回放 <0.5%。
- Q7 点估计达到预注册 MDE 且 95% 置信区间下界 >0 才通过因果 Gate；达到功效样本后若区间上界仍低于 MDE，才判定“不足以继续扩展”。
- 除上述 `PASS` 与 `NO_EXPAND` 两种互斥结果外，其余情况全部标记 `INCONCLUSIVE`，包括区间同时覆盖 0 与 MDE，或区间不跨 0 但点估计尚未达到 MDE；此时延长冻结窗口或停止作因果宣称，不能把统计不确定误判为功能失败。结果不与上一阶段的混合版本直接归因比较。
- 核心流程通过 WCAG 2.2 AA，外部审计无严重问题。
- 5% → 25% → 100% 灰度可用；自动回滚目标 <10 分钟。

只有此阶段数据证明异步社交有价值，下一阶段才可选择投资账号、云档、好友关系或公开榜单；它们不是本阶段既定交付。

### M14–18：十关收口与下一周期决策（2027-10 至 2028-01）

主要交付：

- 完成其余 Wave C、Wave D 和十关系统化改造；若现有十关未全部过 Gate，其他扩展一律让路。
- 建立每周认证规则轮换、每月三关专题；高质量新 3D 主题包最多每 4–6 个月一个。
- 完成安全响应头、制品签名、SBOM、内容包独立回滚和正式发布证据链。
- 根据 M11 试点，最多选择一项在线扩展（账号云档、好友关系、公开榜单三者之一）进入下一周期设计，不在本阶段同时建设。
- 形成新主题 M18 决策包；建议候选为“地铁维护站”，规则重点是列车/通风噪声与周期通路，而不是只换皮。

M18 新主题启动门槛：

- 前五阶段关键 KPI 全部通过，内容流水线连续两个版本不需核心运行时专项修改。
- 十关已经全部通过对应 Gate，且现有主题没有阻断级音画、设备或可访问性债务。
- 新主题只在 M18 后的下一规划周期启动；上限建议为 3 关、9 个 Remix、1 条敌人规则、1 个主动机关和独立音乐包，正式排期目标 ≤16 周。
- 若准入门槛未满足，不启动新主题；继续生产现有主题的低成本认证合同。

## 9. 技术与内容生产主线

### 9.1 架构拆分

采用“冻结接口、逐块抽离、每步回放等价”的方式：

1. 抽离场景生命周期与 WebGL 资源释放。
2. 抽离资产清单、流式加载、缓存和错误恢复。
3. 抽离渲染质量、镜头、遮挡和后期。
4. 抽离 HUD、输入、无障碍 DOM 和暂停。
5. 抽离音频事件、音乐状态和字幕/震动替代。
6. 抽离回放、运行记录、遥测适配器和存档迁移。

不以“每个文件必须小”为唯一目标，但业务模块应有单一责任；约 1,500 行是审查警戒线，不是机械切文件指标。任何拆分均不得改变确定性模拟结果。

### 9.2 加载与仓库体积

- Three.js 核心、游戏壳、当前主题、当前关卡和结算资产独立分包。
- 主题与下一关只在明确意图后预取；警察和胜利演出保持接近出口加载。
- 运行资产采用内容哈希 URL；浏览器缓存和 Service Worker/IndexedDB 必须先过 Safari 存储与更新验证。
- `art-source/` 只保留当前可编辑母版、必要贴图与许可证；评审导出、旧候选和重复烘焙不进 Git。
- 运行时派生资产与源母版分层；大文件使用受控 LFS 或内容制品，不让普通 Git 历史无限增长。
- 每个新机制必须从当期构建资产预算中“先腾空间再接入”，不允许为了接功能直接抬高质量配置的硬门槛。
- WebGPU 可以做非阻塞试验，但 18 个月内 WebGL 2 仍是发布基线，不能让新渲染后端拖住核心玩法。

### 9.3 内容数据化

`LevelPackage` 至少包含：

- 版本、规则集、关卡 seed 与兼容范围。
- 导航、碰撞、视线遮挡、出生、出口和可达性。
- 藏点类型、锚点、专属资产和动作合同。
- 任务图、分支、重试、软锁保护和精通目标。
- 机关、成本、证据、冷却和事件导演标签。
- 灯光、后期、音频、环境故事簇和质量档。
- 运行资产依赖、哈希、许可、LOD、KTX2 和预算报告。

目标是“新增关卡不改核心运行代码”，不是把 TypeScript 硬编码机械地搬成难以验证的 JSON。Schema、编辑器和验证器必须一起交付。

### 9.4 美术、动画与音乐生产

每项新玩法同步开四条生产线：

- **Lookdev**：先冻结材质、尺度、磨损逻辑、灯光和构图，不在十关分别猜风格。
- **模型**：英雄交互物有内外结构、机械逻辑、锚点、LOD 和碰撞；远景模块控制重复感与轮廓。
- **动画**：角色接触、道具响应、逻辑 marker 和音效事件使用同一时间线；转场、足锁和穿模进入自动/人工接触表。
- **音频**：交互 Foley、环境声、音乐 stem、字幕和震动替代同批验收；音乐原型不得用蜂鸣或临时 loop 冒充。

视觉差分只负责发现变化，不能替代审美判断。每个候选必须同时具备固定种子截图、动作接触表、运行录屏和人工美术批准。

### 9.5 测试与发布金字塔

以下是目标态，不是对当前 CI 能力的宣称：

| 层级 | 目标覆盖 | 最迟启用 |
| --- | --- | --- |
| 每个 PR | 现有类型、Lint、单元、确定性、AI 隔离、资产合同、双 clean build、依赖审计；新增 Chromium 核心冒烟、axe 和短生命周期资源释放 | M0–2 |
| 每晚 | Chromium/WebKit/Firefox、十关与 Remix、视觉差分、弱网、资源失败、20 分钟内存和 WebGL context soak | 核心项 M0–2，完整三浏览器在 M5 前 |
| 每个候选版本 | 真机矩阵、音频解锁、后台恢复、键鼠/触摸/Gamepad、WCAG、所有正式资产重建与人工美术评审 | Gold 最小集 M2–5，完整集 M11–14 |
| 发布后 | 合成探针、首局资源状态、RUM SLO、错误率、回放失败率和回滚演练 | 最小健康/人工回滚 M0–2，自动灰度 M11–14 |

每次发布仍要求 Git SHA、构建产物、截图证据与部署版本完全一致。

## 10. 数据与隐私

遥测只收集改进游戏所需的最小数据：

- `run_start` / `run_end`
- `objective_plan_selected` / `objective_completed`
- `evidence_created` / `enemy_state_transition`（聚合或采样）
- `hide_enter` / `hide_exit` / `mechanic_activated`
- `caught_reason` / `retry`
- `performance_sample` / `asset_failure` / `context_recovery`

约束：

- 每局使用匿名 run ID；只有明确同意产品遥测后才生成随机 `anonymousInstallId` 计算跨会话 cohort。两者都不采集联系人、精确位置、广告标识或跨站追踪信息。
- `anonymousInstallId` 可随时撤销和删除，不使用指纹恢复；清站点数据即重置，多设备默认不合并。
- 拒绝遥测的玩家不进入远程 Q7 分母，游戏与本地进度不受影响；报告必须披露同意覆盖率。
- 远程回放必须征得同意，设置 TTL、访问审计和删除入口。
- 原始按键只用于确定性回放，不用于推断身份；公开分享前先由服务器复验并剥离设备信息。
- 数据量不足或完整率 <98% 时，不能用残缺漏斗作重大玩法决策。
- 辅助模式和无障碍设置不得进入公开排名标签或被用于歧视性分组。

## 11. 优先级、依赖和明确不做

### 11.1 关键依赖顺序

| 先完成 | 才能开始 | 原因 |
| --- | --- | --- |
| 证据协议与确定性版本 | 新诱饵、双敌人、事件导演 | 防止功能绕过公平 AI |
| 黄金样板 | 十关批量迁移 | 先证明玩法语言和生产成本 |
| 回放与遥测基线 | 平衡、周合同、Ghost 分享 | 没有证据无法判断是否有效 |
| 内容 Schema 与验证器 | 新主题与规模化关卡 | 避免每关继续工程硬编码 |
| 真机与加载余量 | 双敌人、新英雄资产 | 防止内容一加就突破 Web 预算 |
| 服务端复验与隐私 | 公开榜单、云 Ghost | 防止无效成绩和数据风险 |

### 11.2 18 个月内明确不做

- 不做实时 PvP、实时合作、开放世界或 3D 社交大厅。
- 不做无限程序化迷宫；继续使用可审计、可复现的认证变体。
- 不做速度、视距、隐身值等永久数值养成，不做抽卡、装备战力或付费优势。
- 不增加战斗、复杂背包、制作系统和多按钮技能栏。
- 双敌人验证前不扩到三名以上，不把共享黑板变成全知蜂群。
- 没有服务器复验和举报机制前，不开放全球榜单或公开 UGC。
- 核心指标未通过前，不制作第二个新主题包。
- 不为了“次世代”标签把 WebGPU 变成关键路径，不为了性能退回简单几何美术。

## 12. 止损、降级与冻结规则

长期计划必须允许删功能，而不是只会继续叠补丁。

| 触发条件 | 必须动作 |
| --- | --- |
| 新机制按预注册主指标完成两轮充足样本后仍无达到最小有效改善 | 标记 `REJECTED` 或回退为单关可选合同，不继续扩散 |
| 任一轮理解错误上升 ≥5 个百分点，或公平性跌破对应全局底线 | 立即回退该机制；不得等待 Q7 或重试率补偿 |
| 双 AI 两轮后“不公平”反馈 >8%、Standard 通关率 <25% 或低端移动 P95 >33 ms | 降级为单关演出或恢复单敌人 |
| Ghost 连续两个月参与率 <15%、分享打开率 <8% | 保留本地 Ghost，停止扩大后台投入 |
| 新三关章节合资格完成率 <25%，且制作超过 16 周 | 停止新主题，改做现有主题认证合同 |
| 无崩溃会话 <99% 或首局 P75 连续两版 >8 秒 | 冻结内容开发，先恢复技术基线 |
| 任一候选出现 AI 读取隐藏位置、正式资产缺失、几何占位回退或回放版本串线 | 阻断发布，无例外放行 |
| 某策略在熟练玩家中连续两轮占比 >70% | 先修成本、信息和关卡结构，不用简单数值砍速度 |

## 13. 团队能力与发布节奏

建议按以下能力配置估算 18 个月：

- 1 名 Web / 图形运行时工程师。
- 1 名玩法 / AI / 工具工程师。
- 1 名技术美术，覆盖 Blender、材质、LOD 与运行资产。
- 1 名关卡 / 系统设计，可与玩法工程兼职但必须有明确验收责任。
- 0.5–1 名自动化 QA / 发布运维。
- 角色动画、音频和无障碍专家按阶段参与。

若长期只有 1–2 名核心人员，阶段顺序和退出门槛不变，整体时间按约 1.8–2.5 倍延长；优先保留黄金样板、拆包、真机、内容数据化和自动视觉 QA，延后云档、公开榜单与新主题。

产能预算用于防止阶段超卖：

- Gold Standard：约 24–36 个跨职能人周，包含设计、玩法、技术美术、动画/音频与 QA。
- 使用已批准系统迁移一关：约 6–10 个跨职能人周；新增英雄道具或专属角色动作另计。
- 双敌人代表关：在关卡迁移之外增加约 12–18 个玩法/动画/QA 人周。
- 全新三关主题：约 40–60 个跨职能人周，因此只能在 M18 后单独立项。

## 15. 每个阶段的完成定义

一个阶段只有同时满足以下条件才算完成：

1. **玩法**：目标体验真实发生，不只是配置项或测试桩存在。
2. **公平**：AI 输入来源可追溯，信息隔离自动回归为 0 违规。
3. **美术**：玩家可见对象均为批准的正式 3D 资产，材质、灯光、动作和接触达到该镜头距离的成品标准。
4. **音频**：关键状态有正式音效/音乐、响度与授权记录，并有非音频替代。
5. **交互**：桌面、触控、Gamepad（启用后）和辅助模式共用规则，不出现方向反转、粘键或遮挡。
6. **性能**：目标设备和弱网预算通过，新增功能没有靠隐藏角色或删除关键美术达标。
7. **确定性**：30/60/120 Hz、回放、规则版本和存档迁移均通过。
8. **质量证据**：自动测试、固定种子截图、运行录屏、真机矩阵和人工体验审查来自同一候选提交。
9. **发布**：远端 commit、制品、部署和证据一致，具备回滚方案。
10. **产品结果**：阶段 KPI 达标；未达标则按止损表返工、缩小或停止，不能只凭“功能已做完”进入下一阶段。

## 16. 最终决策原则

未来 18 个月最重要的取舍是：

> **先把“玩家可以主动骗过一个公平而聪明的系统”做成，再扩大内容和在线规模。**

这意味着近期最值得投入的是图书馆黄金样板、证据驱动的环境操纵、真实分支目标、三类藏点的正式表现、架构拆分、真机性能和内容工具。双敌人、异步挑战链接与新主题都保留清晰方向，但必须在前置指标通过后依次解锁。

只要这条顺序不被打乱，十关就不再只是十张更复杂的迷宫，而会成为一套能持续扩展、可复玩、可理解并且保有高质量 3D 表现的潜行系统。
