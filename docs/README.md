## 1. 五类事实源

| 事实类型 | 当前权威来源 | 使用规则 |
| --- | --- | --- |
| 产品方向与长期排序 | [`13_长期产品与技术路线图_2026-2028.md`](13_长期产品与技术路线图_2026-2028.md) | 决定为什么做、先做什么、何时停止；不复制运行常量 |
| 机制与内容合同 | `app/game/` 中的版本化合同、对应自动测试；现有设计文档提供意图与制作依据 | 文档和代码冲突时先阻断变更并补设计决策记录，不从旧文档直接抄参数 |
| 运行常量与规则版本 | TypeScript 配置、资产 manifest、存档/回放版本和测试断言 | 数字只维护一份；说明文档引用来源，不另建易过期副本 |
| 质量与发布门禁 | `package.json` 脚本、`.github/workflows/`、`tests/` 和构建审计 | 当前命令输出决定 PASS/FAIL；README 不手写测试数量 |
| 发布事实与证据 | 与 Git commit 和部署版本绑定的不可变发布报告 | 历史报告只证明对应候选版本，不代表当前 HEAD 或线上最新版本 |

任何新文档必须先声明自己属于哪一类。一个文件不能同时充当未来承诺、运行参数和当前发布证明。

当前经确认的发布指针：[`releases/LATEST.md`](releases/LATEST.md)。

## 6. M0–2 文档治理任务

长期路线图前两个月内完成以下迁移：

1. 把当前 GDD、潜行/AI、输入/镜头、关卡、任务和进度拆成清晰的产品与设计合同。
2. 把唯一性能预算、设备矩阵、发布门禁和证据策略集中到 `quality/`。
3. 把历史实施报告移入 `archive/` 或按 commit/version 组织的 `releases/`。
4. 建立轻量 ADR，记录影响公平性、存档、回放、资产 Schema 和性能预算的决策。
5. README 最终只保留简介、快速运行、本阶段入口、质量门禁和最新发布链接。

完成迁移前，遇到冲突必须回到代码、测试和对应候选版本证据核对，禁止选择最宽松的一套数字放行。
