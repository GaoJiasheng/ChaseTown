## 0. 结论先行

M0 没有改动产品代码、玩法、资产、测试或管线。除前置锚点
`docs/15_本地精华移植施工单.md` 外，本阶段只增加本报告和浏览器原始证据。

审计推翻或修正了四个移植预设：

1. 远端运行态不是无骨骼的几何占位小人。Kid、Villain、Police 的
   `*-bootstrap.glb` 都是正式蒙皮角色的首绘衍生物，保留 21 关节、完整几何
   和远端玩法专用动画；目前是 bootstrap 常驻，不存在随后升级到 LOD1/high
   的角色流式晋升。
2. 远端不是空白动画系统。它已有 Kid 12、Villain 8、Police 5 个状态专用
   clip，覆盖藏入/藏中/窥视/藏出、搜寻、查柜、抓捕与胜利。直接用本地九
   clip GLB 覆盖会因必需 clip 缺失而在首绘阶段抛错。
3. 远端没有“C 蹲伏”。`Q` 是自由态轻步、藏身态窥视，`C` 是抹除证据，
   `E` 是交互/藏身。M1 不应新造 Crouch 机制，也不能覆盖 C 键；应保留远端
   Hide 动画契约。
4. 远端已经有 Meshopt + KTX2、bootstrap/LOD1、RoomEnvironment/PMREM、
   各向异性过滤、批处理环境和动态质量档。M2/M3 应补缺和统一门禁，不能
   把本地旧管线或同类渲染实现整体覆盖过来。

推荐裁决：M1 仍从 Villain 开始，但把目标改为“在正式俯视相机下提升剪影、
材质分区和辨识度”，视觉模型择优来自本地线，动画与加载契约以远端线为
权威。M0 提交后停止，不进入 M1。

### 2.2 贴图与 bootstrap 的真实含义

- Kid high/LOD1：3 张 UASTC KTX2；Normal/ORM 768²，BaseColor 2048²。
- Kid bootstrap：同一 LOD1 几何，3 张 512² UASTC KTX2。
- Villain high/LOD1：3 张 UASTC KTX2；Normal/ORM 768²，BaseColor 2048²。
- Villain bootstrap：同一 LOD1 几何；Normal/ORM 512² UASTC，BaseColor
  1024² ETC1S。
- Police high：7 张 768²–2048² UASTC KTX2。
- Police bootstrap：同一 high 几何；4 张 512² UASTC Normal/ORM，加脸部

既有真实浏览器比较报告给出的 bootstrap 对参考模型结果为：Kid silhouette
IoU 1.0 / RGB MAE 0.4406，Villain 1.0 / 0.6699，Police 1.0 / 0.5592。
因此 bootstrap 并未把角色替换成几何色块；它主要降低纹理成本。

### 3.4 当前 draw calls / triangles / shadow 的证据边界

当前代码确有只读 QA hook：`getState().render` 返回 `calls`、`triangles`、
理论 `shadowTriangles/shadowDrawCalls`、memory/program/texture 等。每帧在唯一
正式 render 前执行 `renderer.info.reset()`，所以 `calls/triangles` 是含阴影
pass 的整帧 WebGLRenderer 提交；`render.shadow` 则是 scene traversal 的理论
分解，两者不能混为同一口径。

本次 in-app 浏览器能确认正式页面 ready、正式机位和真实资源请求，但其页面
读取运行在隔离 world，无法访问 main world 的 `window.__CHASING_QA__`。因此：

- **本报告不提供当前 draw calls / triangles / shadow 的伪数字**；
- 不把 `quality.ts` 上限冒充实测；
- 不沿用 `docs/web-rendering/evidence/deployed-v13` 的旧 520 calls / 1,999,402
  triangles，因为旧证据早于当前 `8d6b0ca`。

独立复测的标准方法已经存在于 `scripts/environment-art-qa.mjs`：固定
1280×720 + `?qa=1&qaQuality=high`，等待 `ready`、`decorativeReady`、
`deferredDressingSettled`、`qaDecorativeSceneCompiled`、`compileCount===1`、
`prewarmCount===1`；锁定质量档和导演，逐关 `selectLevel`、进入 playing、
设置固定 scenario，连续 rAF 采样 1 秒后读取 `getState().render`。M3 的任何
前后对比必须先按此法重建当前 commit 的有效基线。

这项缺口本身也支持 M3 先补 render 分类分解：当前 QA 只能给总量，不能解释
角色、迷宫、道具和阴影各占多少。

### 3.5 现有压缩和质量管线

- 现有 36 个模型 GLB 全部实际使用 Meshopt + KTX2/Basis。
- 0 个 Draco；运行时没有 DRACOLoader。
- 0 个 `EXT_texture_webp` / 内嵌 WebP；远端生产格式是 KTX2，不是 WebP。
- `optimize_character_runtime.mjs`、`optimize_runtime_ktx2.mjs`、角色/主题
  bootstrap 生成器均是真实生产管线，不是仅有 Vite 配置线索。
- `quality_gate.py` 有 stddev 门禁，candidate 会运行固定版本 glTF Validator；
  但 KTX2 最终产物缺一个统一的 post-conversion Validator + stddev CI 门禁。
- 资产 URL 的 `?v=` 分散为 1、2、5、32 等值，没有本地线式的单点
  `ASSET_VERSION`。
- `tools/art_pipeline/README.md` 中 “no KTX2” 的描述已经落后于实际产物。

## 4. M0-3 渲染与质量现状

状态：**完成**。

### 4.1 已有能力

- WebGLRenderer：桌面抗锯齿、移动端关闭 AA；sRGB；ACES Filmic；曝光按关卡。
- 阴影：PCFShadowMap；主 Directional Light 投影，暖色 Directional 不投影；
  动态 Point/Spot 仅选择近距优先项且不投影。
- 环境：FogExp2、HemisphereLight、RoomEnvironment + PMREM；PMREM 产物和
  generator 在 cleanup 中 dispose。
- 纹理：资产纹理与运行时 CanvasTexture 均设置
  `min(8, renderer.capabilities.getMaxAnisotropy())`。
- 环境批处理：墙地已使用 InstancedMesh/BatchedMesh，并有材质 flatten。
- 主阴影相机：high 2048，balanced/mobile 1024；正交范围 ±18 m，near 1、
  far 68；每帧跟随玩家，但没有 texel snapping。
- 质量 governor：1 秒 p95 采样、2.5 秒降级保持、12 秒升级保持，并有三级
  emergency 降级。

### 4.2 `quality.ts` 分档

| 档位 | DPR | 阴影 | 动态灯 | main 预算（tris/calls） | shadow 预算（tris/calls） | 静态环境投影 | 装饰距离 |

| mobile | 1.0 | 1024 | 3 | 900k / 250 | 360k / 70 | 否 | 36m |

### 4.3 明确缺口

- 主阴影相机缺纹素对齐，移动时仍可能有阴影闪烁。

- 无迷宫/建筑阴影代理体。
- 角色是多 SkinnedMesh 直接投影；无角色刚性合批或关节化 shadow proxy。
- QA render 无 actor / maze / props / shadow-pass 分类 breakdown。
