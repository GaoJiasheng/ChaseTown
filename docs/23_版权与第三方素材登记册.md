## 1. 权威边界

本文件是项目第三方输入与发行前置事项的单一索引，不复制所有许可证全文。发生冲突时按以下顺序核对：

1. 固定版本的上游许可证/条款原文与本仓库保存的本地许可文本；
2. 各项 `docs/licenses/*.md` 和角色 `SOURCE_AND_LICENSES.md` 中的逐字节输入记录；

本登记册不会把内部总结提升为许可证本身。发现不一致时必须保留差异、修正较低层记录，并让上游原文优先。

## 3. 已发现的不一致与裁决

1. `public/THIRD_PARTY_NOTICES.txt` 原先仍列 React 19.2.6、vinext 0.0.50、Vite 8.0.13；当前 `package-lock.json` 为 React 19.2.8、vinext 1.0.0-beta.8、Vite 8.1.5。本批已把 notice 中这些版本标签同步到锁文件；许可证正文未据此改写。软件版本以 lockfile 为准。
2. Kid/Police 的旧来源记录写“概念图生成工具未知”。本次从每张已提交 PNG 的内嵌 C2PA claim 恢复了服务、软件代理版本和 claim 日期，故这些字段以 `art-source/Concepts/SOURCE_AND_LICENSES.md` 为准；作者、prompt、参考图、请求主体、适用协议和授权仍未确认，旧记录的发行阻断结论不变。
3. `makehuman-assets` 的 gitlink不能复现审计时使用的全部七项 Police 原始输入；具体字节以 `docs/licenses/MAKEHUMAN_CORE_ASSETS_CC0.md` 的路径、字节数与 SHA 表为准。该裁决不把脏 submodule 状态提交进仓库。
4. `public/THIRD_PARTY_NOTICES.txt` 是部署 notice，不是完整 npm SBOM，也没有汇总所有内部制作源。完整第三方输入以本登记册为入口，运行部署 notice 与各 `docs/licenses/` 记录共同使用。

## 5. Runtime notice 当前结论

- `public/THIRD_PARTY_NOTICES.txt` 位于静态资源目录，历史证据 `docs/web-rendering/evidence/deployed-v13-smoke.json` 记录 `/THIRD_PARTY_NOTICES.txt` 返回 HTTP 200、`text/plain`。
- 本批从无 iCloud 副本的干净快照执行 `npm run build:clean` 后，`public/THIRD_PARTY_NOTICES.txt` 与 `dist/client/THIRD_PARTY_NOTICES.txt` 均为 16,651 B、SHA-256 `ba4a4db11a43b4109b148a0878751dae5a29c6de5e876826a6fd8893948e27b6`，`cmp` 返回 0；这证明当前构建 exact-copy，不替代目标部署 HTTP 验证。
- 当前游戏 UI/README 有仓库内链接，但游戏内没有面向最终玩家的 notice/credits 入口。项目当前不分发，因此本批只登记；是否必须在游戏内提供入口由目标发行地域、平台规则、第三方条款与法务共同决定。
- 最终发行验证必须针对实际目标部署重新访问 URL，不能用本地构建文件存在替代线上可达性。

## 6. iCloud 同步副本审计

2026-08-31 在工作区执行 `git ls-files --others --exclude-standard`，得到 **330 个**未跟踪文件；它们全部符合文件名末尾增加 ` 2` 的模式。按顶层目录分布为：`app` 50、`art-source` 44、`build` 5、`docs` 58、`public` 49、`scripts` 19、`tests` 80、`tools` 25。对 `git ls-files` 运行同一模式，结果为 **0 个已跟踪文件**，因此这些副本不属于版本库内容，也不会进入本批提交。

这些命名与 iCloud Drive 在同步/冲突时产生副本的常见外观一致，但 Git 证据不能确认具体同步事件、时间或进程，故不把成因写成已证实事实。本批没有删除、移动或提交任何副本，也没有用 `.gitignore` 隐藏它们。

建议的本地清理流程（由用户另行执行）：

1. 暂停写入并备份工作区；导出 330 项明确清单。
2. 对每个 `name 2.ext` 与对应 `name.ext` 比较字节数和 SHA-256；不同内容必须人工审阅，不能批量覆盖。
3. 确认 canonical 文件已被 Git 跟踪且内容正确后，再通过 Finder 或经过复核的显式路径列表删除副本。
4. 重新运行 `git status --short`，确保只剩已知的 `tools/third_party/makehuman-assets` 本地脏状态等预存项；不要把副本加入提交。

## 7. 本批验证口径

- 范围：`public/models/`、`app/`、玩法、渲染和测试逻辑必须相对 `origin/main` 零 diff。
- 声明：根 `LICENSE`、`package.json` 与 README 的主体/使用边界一致；主体由产品方提供，不从 Git 猜测。
